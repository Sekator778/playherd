## 0. Коротко

1. PLAY — токен CAT в Chia testnet11, 3 знака после запятой, выпущен один раз: 100 000 000 (`PlayAmount.java:24`, `economy_implementation_plan.md:5`). Цены у него нет.
2. Игрок ставит `stake` на «вверх/вниз» на один раунд (3 или 15 минут) с плечом `L`. Позиция = `stake · L` номинала, маржа = `stake`.
3. К ставке сверху добавляются две комиссии: комиссия Herd `stake · min(cap_share, r_m · k · L)` и фиксированная сетевая 0,1 PLAY. Обе округляются вверх до 0,001.
4. Выплата в конце раунда: `stake · (1 + s · L · R)`, где `R` — ход цены, `s = ±1`; не ниже 0 и не выше `min(20 · stake, 0,1 % казны)`.
5. Если цена касается цены ликвидации, игрок получает остаток маржи по крайней цене свечи, но не меньше 0. Цена ликвидации: расстояние `(1/L − l) / (1 ∓ l)`, `l = κ / cap`.
6. Контрагент каждой ставки — казна (`TREASURY`): проигранная ставка уходит в неё, выигрыш платится из неё, стартовые пакеты тоже из неё. Комиссии идут на отдельный счёт `HERD`.
7. Казну защищают: потолок выплаты, лимит открытого номинала на (рынок, сторона, раунд), общая корзина крипторынков, выключатель (казна < 90 % своего 30-дневного максимума), лимит регистраций, запрет выводить стартовый пакет.
8. Комиссия — это спред Глостена–Милгрома: безубыточная точность игрока `a* = 1/2 + r / (2 · E|R|)` не зависит от плеча. Цель: `a* ≥ 55 %` на любом рынке и в любой длине раунда.
9. Для 1 млн игроков за 2 года нужен выпуск·q ≥ 10¹² (сегодня 10⁸): иначе стартовые пакеты съедают казну (`κ = N · пакет / T`). Это требует нового CAT и 1000 TXCH.

## 2. Ставка

### 2.1 Что покупает игрок

Обозначения: `S` — ставка, `L` — плечо (целое, от 2), `P0` — цена открытия раунда, `R = P_close/P0 − 1`, `s = +1` для «вверх», `−1` для «вниз».

- Номинал `N = S · L`. Размер позиции `Q = S · L / P0` (`PositionSizing.java:29-31`). Маржа позиции = `S` (изолированная маржа, `LiquidationCalculator.java:49-53`).
- Все ставки раунда открываются по цене открытия и закрываются по цене закрытия (Р-8, `economics.md` §2).

### 2.2 Выплата при расчёте (без ликвидации)

`выплата = max(0, S + s · Q · (P_close − P0)) = max(0, S · (1 + s · L · R))`

в коде `LiquidationCalculator.java:109-114`, `GameEngine.java:214-218`. Игрок получает ставку плюс/минус `S · L · R`. Ничья (цена закрытия = цене открытия): ставка возвращается, комиссии не возвращаются (`economy_implementation_plan.md` A4; в коде комиссии возвращают только отмена и отменённый раунд, `GameEngine.java:165-174`).

Потолок выплаты: `min(20 · S, 0,1 % казны)` (`EconomyRules.java:39,47,93-103`, применяется в `GameEngine.java:219-223`). Казна для потолка — баланс `TREASURY`, до переключения — константа 99 998 100 (`LedgerBook.java:831-834`). Пример [вывод, арифметика]: при казне ~10⁸ потолок по казне 99 998 PLAY ниже `20 · S` уже при `S ≥ 5000`; при казне 10¹² он 10⁹ PLAY и не мешает.

Движение денег при расчёте: `TREASURY += S − выплата`, игрок получает выплату (`LedgerBook.java:326-333`).

### 2.3 Ликвидация

Цена ликвидации (формула Hyperliquid, `LiquidationCalculator.java:67-86`):
- лонг: `P_liq = P0 · (1 − 1/L) / (1 − l)`; шорт: `P_liq = P0 · (1 + 1/L) / (1 + l)`;
- расстояние до неё: лонг `(1/L − l)/(1 − l)`, шорт `(1/L − l)/(1 + l)` [вывод, алгебра из формул выше].

Поддерживающая ставка `l = κ / cap(рынок, длина раунда)`: `κ = 0,1` для рынков цен, `0,5` для рынков шансов (`MarketSpec.java:129-131`, `MarketEconomy.java:25-26`). На плече `L = cap` расстояние до ликвидации ≈ `(1 − κ)/cap` и позиция в момент касания барьера стоит `κ · S` [вывод, подстановка].

Проверка: на каждой свече пути раунда, лонг ликвидируется, если `low ≤ P_liq`, шорт — если `high ≥ P_liq`; проверка идёт до расчёта по закрытию (`PositionSimulator.java:55-85`).

**Что платится при ликвидации** («в коде», ставки по новым правилам): остаток маржи **по крайней цене той свечи, на которой сработала ликвидация** — минимум свечи (лонг) или максимум (шорт):

`выплата = max(0, S + s · Q · (P_ext − P0))`, без штрафа; гэп сквозь маржу даёт 0 (`LiquidationCalculator.java:129-139`, `GameEngine.java:209-213`). Прежнее правило «0 при ликвидации» (Р-7) осталось только для старых ставок без комиссий (`GameEngine.java:198-208`).

### 2.4 Ступени плеча по размеру ставки

Чем крупнее ставка, тем ниже допустимое плечо (`EconomyRules.java:34-36`, `:52-67`): `maxL = min(cap, max(2, cap / d))`, `d = 1` при `S ≤ 250`, `2` при `S ≤ 500`, `5` при `S ≤ 1 200`, `10` выше (целочисленное деление).

Пример BTC, 3 минуты (`cap` 1200): S ≤ 250 → ×1200; ≤ 500 → ×600; ≤ 1200 → ×240; больше → ×120. Рынок шансов (`cap` 10): S ≤ 250 → ×10; ≤ 500 → ×5; ≤ 1200 → ×2; выше → ×2 [вывод, расчёт по формуле].

## 3. Комиссии

### 3.1 Формула

Для ставки `S`, плеча `L`, рынка с `r_m` (в долях номинала: 1 б.п. = 0,0001):

| | До `8a08638` | С `8a08638` (Р-102) |
|---|---|---|
| Доля Herd | `min(1 %, r_m · L)` | `min(20 %, k · r_m · L)` |
| `k` | нет | 1 в 3-минутном раунде; **2,2** в 15-минутном (цены); **3,0** в 15-минутном на шансах |
| Комиссия Herd | `S · доля`, округление вверх до 0,001, не меньше 0,001 | то же |
| Сетевая | 0,1 PLAY за ставку | то же |
| Списывается со счёта | `S + Herd + сеть`, баланс должен покрывать сумму | то же |

Источники: сегодня — `EconomyRules.java:32,83-91`, `:28-30`, списание `LedgerBook.java:246-271`; Р-102 — `decisions.md` Р-102, `economy_variant_a_rules_2026-10-17.md` §0.1 правила 2а–2г. Потолок 20 % — только страж: ни одна клетка рынок × длина раунда его не достигает (максимум 15,4 %, TSLA, 15 минут; там же §2.3).

Правила, которые не меняются:
- Комиссии, взятые со ставки, хранятся в самой ставке; смена правил не меняет уже поставленные ставки (`Fees.java:7-9`).
- Отмена ставки до старта раунда или отмена раунда возвращают ставку и обе комиссии (`GameEngine.java:155-174`, `LedgerBook.java:277-291`).
- Обе комиссии идут в `HERD` (после переключения экономики; до него «просто потрачены») (`LedgerBook.java:266-270`).
- Раз в сутки комиссии, заплаченные ботами, переводятся `HERD → TREASURY`; комиссии людей остаются в `HERD` (`LedgerBook.java:689-700`, `GameService.java:2407-2440`).

Почему именно так (Р-91, Р-92): комиссия пропорциональна номиналу (как у Hyperliquid и GMX) и берётся один раз на входе. Потолок 1 % ломал пропорциональность: выше `L_c = 1 %/r_m` (BTC ≈ 109) комиссия переставала расти, а выигрыш информированного растёт ∝ `L` (§5.2).

## 4. Защита казны

Казна — контрагент всех ставок. Её защищают пять слоёв. Все, кроме потолка выплаты, работают только после переключения экономики (`GameService.java:2314-2316` для лимитов, `LedgerBook.java:849-852` для выключателя).

### 4.1 Потолок выплаты одной ставки

`min(20 · S, 0,1 % казны)` — см. §2.2. «в коде» `EconomyRules.java:93-103`.

### 4.2 Лимит на (рынок, сторона, раунд)

Открытый номинал `Σ S·L` одной стороны одного раунда одного рынка не больше

`limit = share · TREASURY / stress(рынок, длина раунда)`, `share = 0,0025` (0,25 %)

«в коде» `EconomyLimits.java:25,34-37`, `GameService.java:2311-2345`. Смысл: если цена пройдёт против казны на stress-ход (99,9-й перцентиль хода за раунд), казна теряет не более 0,25 % себя [вывод по комментарию `EconomyLimits.java:13-15`].
- `stress` 15-минутного раунда = `stress` 3-минутного · 2,2 (`MarketEconomy.java:38,86-90`): медианное отношение σ(15)/σ(3) двенадцати рынков, 2,0–2,4 (`game_economy_math.md` п. 1; перенос на 99,9-й перцентиль — вывод, помечен в комментарии кода).
- Стороны «вверх» и «вниз» считаются отдельно (`GameService.java:2320`). Ставка, которую игрок заменяет, в открытый номинал не входит.
- Отказ называет остаток лимита и максимально допустимую ставку при выбранном плече (`GameService.java:2335-2343`).

Пример (казна 10⁸ PLAY, цифра для порядка величины, текущий баланс `TREASURY` неизвестен). BTC, 3 минуты: `0,0025 · 10⁸ / 0,00817 = 30,6 млн` номинала на сторону (совпадает с `game_economy_math.md` п. 8); 15 минут: stress `0,00817 · 2,2 = 0,017974` → 13,9 млн. Рынок шансов: `0,0025 · 10⁸ / 0,20 = 1,25 млн`.

### 4.3 Корзина крипторынков

Крипторынки двигаются вместе (корреляция 0,70–0,91, `game_economy_math.md` п. 8), поэтому на одной стороне одного раунда сумма `Σ номинал · stress` по всем крипторынкам не больше `1 % · TREASURY` (`EconomyLimits.java:27,39-42,69-83`, `GameService.java:2319-2332`). Свободное место для рынка: `(лимит корзины − уже занято)/stress`; ставка принимается, если влезает и в лимит рынка, и в корзину. Каждый отдельный рынок ограничен 0,25 %, поэтому шесть крипторынков, нагруженных до своих лимитов, дали бы 1,5 % и упёрлись бы в корзину 1 % [вывод, арифметика; состав категории CRYPTO по коду не перечислял].

### 4.4 Выключатель

Условие: `TREASURY · 10 < max30 · 9`, где `max30` — наибольший за последние 30 UTC-суток дневной максимум баланса `TREASURY`, текущий включён (`LedgerBook.java:72-76,677-681,836-856`). То есть казна строго ниже 90 % максимума.

Действие: **новые** ставки получают плечо не выше `max(2, cap/4)`, а также не выше ступени по размеру ставки (`EconomyLimits.java:44-47`, `GameService.java:857-868`). Ставки не останавливаются, открытые ставки платятся как обычно, смена состояния пишется в журнал (`GameService.java:2280-2305`). До переключения экономики всегда закрыт.

### 4.5 Прочее против выкачивания

- Стартовый пакет не выводится: `withdrawable = баланс − выданные пакеты` (§1.3). Пара своих аккаунтов (один в лонг, другой в шорт) убыточна: ожидание пары = −(две комиссии) на каждом плече, перевод 10 000 PLAY таким путём стоит комиссий в 1,2–39 раз больше переводимой суммы (`economy_1m_players_2y_2026-10-17.md` §3.7, оценка [вывод]).
- Лимит регистраций 3 с IP в сутки (§1.2). Sybil без проверки личности неустраним (Douceur 2002), его ущерб ограничивается ценой и размером пакета.
- Переключатель «пакет в очках» для основной сети: **отложено** (Р-101 п. 4).

### 4.6 λ = 0,05 (только с новым выпуском)

Правило 1 варианта А: обе доли лимитов умножаются на `λ = 0,05` без пула: `share` 0,0025 → **0,000125**, доля корзины 0,01 → **0,0005**; предложено одной константой `RISK_LAMBDA` (`economy_variant_a_rules_2026-10-17.md` §0.1, §1). Для рынков шансов дополнительно `stress` 0,20 → **1,00** для обеих длин раунда без множителя 2,2 (там же правило 3).

Почему ждёт нового выпуска (примечание архитектора в начале `economy_variant_a_rules`): при сегодняшней казне ~10⁸ лимиты стали бы слишком жёсткими. Лимит стороны шансов сегодня `0,0025 · 10⁸ / 0,20 = 1,25·10⁶` номинала, с правилами 1 и 3 — `0,000125 · 10⁸ / 1,00 = 1,25·10⁴`, то есть около одной ставки на сторону за раунд [вывод, арифметика]. При `T = 10¹²` те же правила дают для BTC (3 мин) `0,000125 · 10¹² / 0,00817 = 1,53·10¹⁰` и корзину `5·10⁸` (тесты правила 1, там же §4). Поэтому в коде λ и stress шансов должны стать настройкой, включаемой вместе с новым выпуском, а не константой.

## 5. Почему эти числа

Методы выбраны по Р-99: сначала опубликованное, своё — с пометкой. Источники и уровень прочтения — `economy_literature_2026-10-17.md` §0 и `economy_1m_players_2y_2026-10-17.md` §1; новых ссылок здесь нет.

### 5.1 Что теряет игрок без навыка

Для мартингальной цены ожидаемая выплата позиции равна ставке: капитал позиции `E_t = S(1 + s·L·(P_t/P0 − 1))` — мартингал (теорема об остановке, `game_economy_math.md` §0). Следствие:
- если остаток при ликвидации возвращается целиком, `E[выплата] = S`, и игрок без навыка (`a = 0,5`) теряет только комиссию;
- если не возвращается: `E[выплата] = S − P(ликв) · l · L · S`.

Сегодняшняя выплата — остаток по крайней цене свечи, то есть не больше остатка на барьере; значит, к комиссии добавляется небольшая «ликвидационная часть» [вывод]. По прогонам на реальных окнах она мала: ожидание неумелого игрока BTC ×600 — −1,06 % при комиссии 1,01 % (`economy_variant_a_rules` §2.3, таблица).

### 5.2 Безубыточная точность `a*`

Игрок с точностью `a` (доля раундов, где направление угадано) выигрывает в среднем `(2a − 1) · L · E|R|` ставки при комиссии `r · L` (где `r = k · r_m`, доля номинала). Приравнивая:

`a* = 1/2 + r / (2 · E|R|)`

Плечо сокращается, поэтому `a*` от плеча не зависит, пока работает пропорциональная комиссия и нет ликвидации. Основа — спред Глостена–Милгрома (1985): спред покрывает ожидаемый выигрыш информированных; см. также Shin (1991, 1992) и Kyle (1985) в обзоре (`economy_literature_2026-10-17.md` §0.1, строка 5). Вывод формулы и прогон на реальных окнах — `economy_variant_a_rules` §2.2 [вывод].

Что показали расчёты (`out_a3.txt` по `economy_variant_a_rules` §2):
- Сегодня в 3-минутном раунде `a*` BTC: 56,7 % до ×100, но 53,1 % на ×240 и 51,1 % на ×1200 (потолок 1 % перестаёт расти с плечом, выигрыш растёт ∝ `L`).
- В 15-минутном раунде `a*` низка при любом плече (BTC 53,1–53,3 %): средний ход за 15 минут в 2,22–2,23 раза больше (E|R| BTC 6,95 → 15,44 б.п.), а комиссия та же. Отсюда `k = 2,2`.
- `r_m` ETH, SOL, DOGE, XRP, HYPE были 1,0, а правило `r_m = 0,1 · σ₃` дало бы 1,34 / 1,73 / 1,72 / 1,53 / 1,57; их `a*` 54,0–54,9 % против 56,6 % у BTC. Принятые 1,05–1,25 — округление вверх до порога.
- Порог **55 %** — [выбор] математика проекта: в модели 1 млн игроков умелое меньшинство имеет точность 0,56–0,65; при 55 % слабейший модельный умелый игрок только-только в плюсе. Формула даёт `r_m = 0,1 · E|R₃|`, округление вверх до 0,05 б.п. Данных о точности реальных игроков на 3-минутных направлениях нет: неизвестно.
- Доля умелых: «менее 1 %» дэй-трейдеров предсказуемо зарабатывают после издержек (Barber–Lee–Liu–Odean 2011); перенос на игру — UNVERIFIED, в моделях параметр 1–3 % с точностью 0,56–0,65.

### 5.3 Доля денег игроков в казне: `κ = N · пакет / T`

Деньги игроков (пакеты) — вход казны в риск. Граница Вилля (1939) для неотрицательного супермартингала: `P(просадка казны ≥ x) ≤ κ/(κ + x)` (при `κ = 1 %`, `x = 10 %` — 9,1 %; `economy_1m_players_2y` §3.3). Для 1 млн игроков, пакета 10 000 и казны `T`:

| T (PLAY) | κ = 10⁶·10⁴/T |
|---|---|
| 10⁸ (сегодня) | 100 (невозможно) |
| 10¹⁰ | 1 |
| 10¹¹ | 0,1 |
| 10¹² | 0,01 (1 %) |

(`economy_1m_players` §3.2.) Сегодня ~1000 новых игроков за 30 суток открывают выключатель, ~10 000 игроков опустошают казну (`LedgerBook.java:667-672`) — арифметика пакетов, а не риск рынка (`economy_1m_players` §0, пп. 1–2). Поэтому **выпуск·q ≥ 10¹²** (q — делитель пакета, ставки и сетевой комиссии; q = 1) — Р-100. Запасной вариант `T = 10¹¹`, `q = 10` ухудшает RTP на ≤ 0,008 п.п.; `q = 100` — на 0,081 п.п. (округление комиссии до 0,001) и не проходит.

### 5.4 Что и чем моделировалось

Данные: 730 суток 1-минутных BTC, ETH, SOL (Coinbase); остальные девять рынков — прокси на тех же рядах; шансы Polymarket — одни сутки, 54 рынка (`economy_variant_a_rules` §0.3, `economy_1m_players` §2.2).
