# Visual direction — Herd as a real game

Дата: 2026-09-25. Отвечает на `audit.md` пункт за пунктом (ссылки — «Отвечает: …») и фиксирует
токены/принципы, которыми руководствуются `result-moment.md`, `live-round.md`,
`implementation-plan.md`. Источники: Р-33 (стиль «игра», как Twitch Predictions), Р-24 (UI на
английском), Р-48 (телефон — полноценная платформа), Р-50 (яркий момент итога), Алекс 2026-09-25
(«монетки прыгают, огоньки, искорки», «созвучно с плечами, с размером выигрыша»),
`.claude/agents/game-designer.md` (честность/game feel).

Ничего из существующих токенов `web/src/index.css:9-57` не отменяется — этот документ
**добавляет** слой поверх (новые токены + переопределения конкретных классов), потому что базовая
палитра уже прошла проверку WCAG AA против всех трёх фонов и переделывать её с нуля — лишний
риск. Новые hex-значения ниже посчитаны той же формулой относительной яркости WCAG, не «на
глаз» — см. таблицу в §1.

## 0. Сдвиг одним предложением

От «список фактов в одинаковых карточках» к «HUD игры»: одно число-герой на каждом экране,
числа реагируют (вспыхивают/крутятся) на изменение, а не просто перерисовываются, две стороны
рынка (UP/DOWN, толпа) всегда визуально — два лагеря, не строка таблицы, риск (плечо,
близость к ликвидации) — физическая шкала/диск, не два слова мелким шрифтом.

## 1. Палитра — новые токены поверх `index.css:9-57`

```css
:root {
  /* --- Game-feel accents: более электрические варианты существующих --up/--down/--accent для
     вспышек, свечений, частиц. Существующие --up (#22c55e) / --down (#f87171) / --warning
     (#f5b93d) остаются для статичного текста/бейджей — не заменяются, не удаляются. --- */

  --win-neon: #3cff8a;           /* WCAG: 14.59:1 / 13.16:1 / 11.74:1 на bg / bg-elevated / bg-elevated-2 — проходит как основной текст на любом фоне */
  --win-neon-strong: #17b95c;    /* 7.48:1 / 6.74:1 / 6.02:1 — тоже проходит текстом, использовать для обводок/pressed-состояний */
  --win-glow: rgba(60, 255, 138, 0.55);

  --loss-neon: #ff3b3b;          /* 5.46:1 / 4.93:1 на bg/bg-elevated (проходит текстом), 4.40:1 на bg-elevated-2 (НЕ проходит мелкий текст — см. правило ниже) */
  --loss-neon-strong: #c81e1e;   /* 3.37:1 / 3.04:1 / 2.71:1 — только крупный/жирный текст ≥24px на bg, иначе только заливки/иконки/бордеры, не текст */
  --loss-glow: rgba(255, 59, 59, 0.55);

  --liq-magenta: #ff2e9f;        /* 5.65:1 / 5.10:1 / 4.55:1 — проходит как текст везде, но с bg-elevated-2 запас всего 0.05 — на этом фоне предпочитать крупный/жирный текст */
  --liq-magenta-strong: #b3006e; /* 2.89:1 / 2.61:1 / 2.33:1 — только заливки/иконки/бордеры, никогда текст */
  --liq-glow: rgba(255, 46, 159, 0.6);

  /* Золото — уже есть в палитре как --focus-ring (#ffd166, 13.40:1 на bg), тот же hex, новое имя
     для монет/огоньков, чтобы не путать смысл "focus ring" с "монета" при чтении CSS. */
  --gold: var(--focus-ring);
  --gold-strong: #e6a92e;        /* 9.27:1 / 8.36:1 / 7.46:1 — проходит текстом везде */
  --gold-glow: rgba(255, 209, 102, 0.55);

  /* Рамп «нагрева» плеча (x2..x40) — 5 именованных остановок, интерполяция между ними на слайдере
     считается в компоненте (LeverageDial), см. live-round.md §1 за точными порогами. */
  --heat-1: var(--win-neon);     /* x2..x8 — спокойно */
  --heat-2: #b6e23c;             /* x9..x15 */
  --heat-3: var(--gold);         /* x16..x24 */
  --heat-4: #ff9142;             /* x25..x33 */
  --heat-5: var(--loss-neon);    /* x34..x40 — опасно */

  /* Длительности/кривые движения — базовые значения; конкретные множители по тиру интенсивности
     см. result-moment.md §2 / live-round.md §1,§4. */
  --ease-out-back: cubic-bezier(0.34, 1.56, 0.64, 1);   /* прилёт карточки итога, "перелёт+возврат" */
  --ease-out-expo: cubic-bezier(0.16, 1, 0.3, 1);       /* фейды/появления */
  --ease-in-expo: cubic-bezier(0.7, 0, 0.84, 0);        /* уход/исчезновение */
  --ease-shake: cubic-bezier(0.36, 0.07, 0.19, 0.97);   /* тряска экрана/карточки */

  --dur-instant: 100ms;   /* отклик на нажатие — потолок из game-designer.md */
  --dur-fast: 180ms;
  --dur-base: 300ms;
  --dur-crack: 220ms;

  /* HUD-типографика для чисел — см. §2. */
  --num-xl: 44px;  /* заголовок момента итога, HUD-баланс на десктопе */
  --num-xl-mobile: 34px;
  --num-lg: 28px;  /* capital, liquidation price, крупные стат-плитки */
  --num-md: 18px;  /* баланс в шапке на телефоне, P&L-тикер */
}
```

**Правило применения loss/liq-текста:** `--loss-neon`/`--liq-magenta` как ЦВЕТ ТЕКСТА — только
на `--bg`/`--bg-elevated` без ограничения размера, и на `--bg-elevated-2` только для текста
`--num-md` (18px)/`--num-lg`/`--num-xl` или `font-weight ≥ 700` (крупный/жирный по WCAG =
достаточно для AA large-text 3:1, здесь запас больше). Мелкий текст (12-14px, обычный вес) на
`--bg-elevated-2` продолжает использовать существующие `--down`/`--danger-text` — они уже
проверены (`index.css`'s собственный комментарий). `--loss-neon-strong`/`--liq-magenta-strong`
— никогда не текст, только заливки/иконки/тени/бордеры ≥3px.

## 2. Типографика

**Решение: не подключать веб-шрифт.** `audit.md` фиксирует, что `--font-family: "Inter"` в
`index.css:54-56` сейчас мёртвая строка (шрифт нигде не загружен) — самый дешёвый и честный
фикс не «наконец подключить Inter» (это сетевой запрос + ~100-150KB даже на один вариативный
файл, бьёт по бюджету производительности телефона из `implementation-plan.md` §5), а **убрать
завязку на недоступный шрифт и осознанно опереться на системный стек**, который уже там —
`-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif`. Системный
шрифт не читается «бухгалтерски» сам по себе — читается таковым при одинаковом размере/весе
везде (`audit.md`, диагноз №2). Фикс — не шрифт, а масштаб/вес/tabular-nums (ниже), это и есть
основной пункт этого раздела.

- Все игровые числа (баланс, итог момента, capital, liquidation price, P&L-тикер, countdown) —
  `font-variant-numeric: tabular-nums`, `font-weight: 800`, размер по токенам `--num-xl/lg/md` из
  §1 (не 13-16px, как сейчас у `.balance-pill`/`.mono`).
- Заголовок момента итога (`+4,960 PLAY` / `−1,000 PLAY` / `LIQUIDATED · −2,500 PLAY`) —
  `--num-xl`, `font-weight: 900`, `letter-spacing: -0.01em` (плотнее на крупном кегле — так цифры
  читаются как единый блок, не как отдельные символы).
- Опциональное усиление (не блокирует релиз — делать, если останется время/бюджет после базовой
  реализации): один самостоятельно захостенный статичный файл дисплейного начертания
  (кандидат — «Space Grotesk» или «Rubik», обе SIL OFL 1.1 — разрешительная лицензия, требует
  проверки актуального текста лицензии на источнике перед использованием — **UNVERIFIED**, в
  проекте не зафиксировано), вес 800, подмножество символов `0-9.,-+$%x ABCDEFGHIJKLMNOPQRSTUVWXYZ`
  (то, что реально попадает в HUD-числа и лейблы), ожидаемый вес файла ~15-25KB woff2 —
  используется ТОЛЬКО через `--font-display` на `--num-xl` элементах, не заменяет системный стек
  нигде больше. Обоснование: даёт более «игровой» характер цифр почти бесплатно по бюджету, но
  не является блокером — HUD уже работает на системном шрифте за счёт веса/масштаба/цвета.

## 3. Иконография

Без иконного шрифта/библиотеки — тот же паттерн, что уже есть в `web/src/components/icons.tsx`
(`DirectionGlyph` — inline SVG в JSX). Новые иконки тем же способом, единый `viewBox`, `currentColor`
где возможно:

- **Coin** — простой диск с ободом (2 контура) + блик, заливка `--gold`, используется в частицах
  и в HUD-балансе.
- **Spark/ember** — 4-лучевая звёздочка (частицы победы / нагрев плеча).
- **Crack** — 2-4 ломаные линии (SVG `<path>` со `stroke-dasharray`, анимируется draw-in/snap —
  `result-moment.md` §2).
- **Flame** — упрощённый силуэт пламени (нагрев плеча x34-40, `live-round.md` §1).
- **Liquidated stamp** — текст «LIQUIDATED» в рамке под углом −8°, псевдо-print текстура через
  `box-shadow`/`filter: blur()` лёгкого смещённого дубля слоя, не растровое изображение.
- **Outcome chips** (`Profile`/`Round` истории, и момент итога) — 🏆 не эмодзи, а тот же
  SVG-паттерн: заливной кубок-силуэт (won), «трещина» (liquidated), нейтральный минус-диск (lost),
  нейтральный диск с двумя горизонтальными линиями — «равно» (even, `result-moment.md` §7).
- **Sound/haptics toggle** (шапка, карточка момента) — та же SVG-иконка, а не platform-эмодзи
  (🔊/🔇/📳/📴): на Android эмодзи-глиф вибрации рендерился мелким нечитаемым тёмным значком.
  Динамик on/off (звуковые волны / волны с крестом) и вибрация on/off (прямоугольник-телефон с
  двумя штрихами по бокам / та же форма перечёркнутая) — `SpeakerOnIcon`/`SpeakerMuteIcon`/
  `VibrationOnIcon`/`VibrationOffIcon` в `icons.tsx`.
- **Wallet ledger, по типу записи** (`ux_spec.md` §8) — подарок (starter pack), фишка-чип (ставка
  списана), стрелка-разворот (возврат ставки/вывода — общая для обоих refund-типов), стрелка вниз
  в лоток (deposit), стрелка вверх из лотка (withdrawal); `SETTLEMENT` без своей иконки — переиспользует
  кубок/минус-диск/равно момента итога по знаку `delta`, а не заводит пятый вариант того же смысла.

## 4. Layout principles (phone-first) — прямой ответ на `audit.md`

- **Hero zone.** Верх каждого экрана — ровно одно число/действие, которому отдан `--num-xl` и
  вся ширина: Home/Round — текущий P&L или countdown; Crowd — capital; Wallet — баланс; Ratings —
  своя позиция в рейтинге (если есть). Всё остальное на экране — ниже и мельче по определению
  сетки, не по случайности вёрстки.
- **Stage/split-camp.** Где есть два противоборствующих направления (bet slip до ставки, список
  позиций раунда после раскрытия) — UP и DOWN всегда две визуально разделённые зоны (цветной
  wash фона своей стороны, не общий серый список), даже когда один из лагерей пуст (показываем
  пустую зелёную/красную зону с «no one yet», не схлопываем).
- **Meter, not text, for proximity.** Любая величина «насколько близко к плохому исходу» (расстояние
  до ликвидации до/во время раунда) — горизонтальная шкала с заливкой и цветом по рампу `--heat-*`,
  никогда голые две строки текста (`LiquidationBar`, `implementation-plan.md` §2).
- **Chips, not bare inputs.** Стейк — крупная цифра + ряд физических «фишек» (MIN/25%/50%/MAX,
  `border-radius: pill`, тень при нажатии), не `<input type=number>` в одиночестве (сам инпут
  остаётся для точного ввода, но визуально вторичен относительно чипов и крупной цифры над ним).
- **Leaderboard cards, not tables.** `Ratings`/топ-5 на Home — карточки строк с рангом-медалью
  (#1-3 — золото/серебро/бронза, лёгкое `--gold-glow` для #1), не `<table>` (сама
  `.data-table--responsive` карточная развёртка на мобильном остаётся как fallback-паттерн для
  длинных списков истории, где иерархия ранга не нужна — Wallet ledger, Profile history).
- **Always one card = one weight class.** Три уровня карточной значимости вместо одного `.card`
  на всё: `.card--hero` (hero zone, крупная тень+обводка чуть ярче), `.card` (текущий, для
  вторичных блоков), `.card--tight` (текущий, для мета-информации/списков) — не новый компонент,
  а модификатор поверх существующего `.card`.
- **Motion is default-on, not default-off.** Единственная анимация сейчас — пульс бейджа `LIVE`.
  Каждый экран получает минимум одно «живое» состояние (countdown-эскалация, pulsing card,
  chart pop-in) — конкретика в `live-round.md`.

## 5. Честные маркеры остаются видимыми, не убивая настроение

Правило-редлайн (`game-designer.md`, «Честность») не меняется: ничего из `DemoBanner`,
`ServerInfoBanner`, `BotBadge`, `OracleDisclosureLine`, `OracleStatusLine`,
`MultiAccountDisclosureLine`, `ResultsHashLine` не уменьшается, не прячется за аккордеон/тултип,
не убирается с первого экрана. Меняется только их визуальный язык, чтобы не выглядеть как
предупреждение антивируса поверх аркады:

- **DEMO-баннер** остаётся первым элементом страницы, той же ширины, не закрываемым, с тем же
  текстом. Визуально — тонкая диагональная штрих-текстура очень низкой непрозрачности
  (`repeating-linear-gradient`, opacity ≤0.06) поверх текущего `--warning-bg`, читается как
  «технический бордюр студии», не как сломанный alert-бокс — цвет текста/фона не меняется
  (контраст уже проверен), меняется только фактура.
  Redline: не WCAG 2.3.1-совместимо мигать — этот элемент вообще не анимируется.
- **Meta rail.** `ServerInfoBanner`, `OracleDisclosureLine`, `OracleStatusLine`,
  `MultiAccountDisclosureLine`, `ResultsHashLine` — визуально сведены к одному повторяющемуся
  паттерну: мелкий моноширинный текст `--text-faint`, без своей карточки/фона, тонкая верхняя
  граница `--border`, всегда прямо под соответствующим блоком (не в футере, не под спойлером) —
  ровно так, как сейчас по составу и месту, просто оформлены как «служебная строка прибора», а
  не как ещё один `.card` того же веса, что и игровой контент. Ничего из этого списка не теряет
  видимость и не требует лишнего тапа.
- **BOT-бейдж** остаётся текстовой плашкой «BOT», без изменений — маленький нейтральный чип уже
  не спорит с игровым визуалом, трогать не нужно.

## 6. Токены движения, звука, вибрации — только указатели

Полные таблицы интенсивности (частицы/тряска/haptics/звук по тирам) — в `result-moment.md` §2 и
`live-round.md` §1/§4, это намеренно не дублируется здесь. Что фиксирует именно этот документ:

- Звук выключен по умолчанию (`localStorage: herd:sfxEnabled`, default `false`), переключатель
  живёт в шапке (иконка динамика рядом с профиль-меню) и повторно — маленькой иконкой на самой
  карточке момента итога (естественная точка обнаружения, не навязчивое «включите звук!»).
- Вибрация включена по умолчанию (`herd:hapticsEnabled`, default `true` — нативная для мобильной
  игры, низкий риск), тот же переключатель рядом со звуком.
- `prefers-reduced-motion: reduce` отключает: тряску экрана, канвас-частицы (монеты/искры/
  конфетти/осколки), анимацию пламени на слайдере плеча, draw-in трещины, bounce-прилёт карточки
  момента. Остаются: цвет, иконка (статичная, без покадровой анимации), текст, мгновенное (без
  roll-эффекта) отображение итогового числа. Это системная настройка ОС, отдельного тумблера в
  приложении для неё нет (переопределять решение ОС — самостоятельный dark pattern).
