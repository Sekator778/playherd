# Live round — the tension phase

Дата: 2026-09-25. Фаза «напряжение» между ставкой и итогом (`game-designer.md`: «предвкушение →
напряжение → удар → награда»). Покрывает: реактивный слайдер плеча в бет-слипе (Алекс: «слайдер
плеча должен нагреваться, с размером выигрыша, чтобы была динамика»), живой P&L-тикер и полоску
до ликвидации во время `RUNNING`, момент раскрытия на старте раунда (D-22), реакцию графика
«толпа vs BTC». Токены — `direction.md` §1. Момент итога (включая LIQUIDATION) — отдельный файл,
`result-moment.md`.

## 1. Leverage dial — бет-слип до ставки

Заменяет неоформленный `<input type="range">` в `BetSlip.tsx` (`audit.md`, раздел Bet slip) —
остаётся настоящим `<input type="range">` под капотом (клавиатурная доступность, screen reader —
нативная семантика бесплатно), визуально — «силовой диск»: заполненный трек с цветом по рампу
`--heat-1..5` (`direction.md` §1), число `x{value}` крупно над треком (`--num-lg`).

| Зона | Leverage | Цвет трека | Поведение при активном drag | Haptic на шаге |
|---|---|---|---|---|
| Calm | x2–x8 | `--heat-1` | нет | нет |
| Warm | x9–x15 | `--heat-2` | лёгкое покачивание ползунка 1px | нет |
| Hot | x16–x24 | `--heat-3` | 1–2 искры/сек хвостом за ползунком | Light impact каждые 5 шагов |
| Danger | x25–x33 | `--heat-4` | 4–6 искр/сек, непрерывная тонкая тряска всего поля 1px | Light impact каждые 2 шага |
| Flame | x34–x40 | `--heat-5` | 8–10 частиц пламени/сек у ползунка, трек пульсирует `opacity .8↔1` 500ms loop даже в покое, тряска поля 1.5px непрерывно | Light impact на **каждом** шаге (throttle ≥80ms между тиками — не сплошной зуммер) + разовый Medium impact при первом пересечении в эту зону |

Частицы/тряска/пульс трека отключаются под `prefers-reduced-motion` — остаётся цвет трека и
число (`direction.md` §6). Haptics — свой тумблер, не завязан на reduced-motion.

## 2. Liquidation preview / live distance bar

Заменяет две строки голого текста в `BetSlip.tsx` (`audit.md`) горизонтальной шкалой:
слева — текущая/входная цена, справа — цена ликвидации, заливка = «сколько ещё есть до края»,
цвет заливки — тот же рамп `--heat-1..5`, но по проценту дистанции, не по leverage напрямую (два
разных входа в один визуальный язык — согласовано, не тот же расчёт):

| Зона | `percentToLiquidation` (до ставки) / живая дистанция (во время раунда) | Цвет | Поведение |
|---|---|---|---|
| Safe | ≥ 50% исходной дистанции | `--heat-1`/`--heat-2` | статично |
| Watch | 25–50% | `--heat-3` | карточка получает медленный пульс, 1.6s цикл (тот же ритм, что текущий `badge--live`, — согласованность) |
| Close | 10–25% | `--heat-4` | пульс карточки ускоряется до 1.0s, стрелка P&L-тикера получает лёгкий bounce на каждом тике |
| Critical | < 10% | `--heat-5` | пульс 0.6s, тонкая магента-обводка карточки (hairline, НЕ заливка — заливка на всю карточку зарезервирована за самим моментом ликвидации в `result-moment.md`, чтобы не путать «почти» с «уже»), однократный (не повторяющийся) Light impact в момент пересечения этого порога |

**Пре-бет версия** (статичный расчёт от `LiquidationPreviewDto`, как сейчас) — работает уже
сегодня, никаких новых данных не требует, просто новый визуальный компонент `LiquidationBar` вместо
двух строк текста.

**Live-версия во время `RUNNING`** — данные для неё уже есть в контракте, не нужно ждать
backend-изменений: `Api.btcReferencePrice(): Promise<MarketReferenceDto>` (`contract.ts:617`,
`{price, asOfMs}`) сегодня используется только для пре-бет превью ликвидации, но ничто не
привязывает его к фазе `BETTING` — тот же метод можно опрашивать на том же 2с поллинг-тике и во
время `RUNNING` (на момент написания в рабочей копии уже появляется `web/src/api/
useReferencePrice.ts` — независимый хук ровно с этой идеей, «poll `btcReferencePrice()`… so a
RUNNING round can show live unrealized P&L», от другого агента, параллельно правящего `web/`;
этот документ на него не полагается напрямую, но подтверждает, что данных достаточно).
`PositionDto.pnl` остаётся `null` до settlement (`contract.ts`: «`pnl` is null until settled/
liquidated»), так что live P&L/дистанция для своей и чужих позиций считаются на клиенте из уже
известных `size`/`entryPrice`/`direction`/`liquidationPrice` (`PositionDto`) и текущего
`price` из `MarketReferenceDto`: `pnl = size × (price − entryPrice) × sign(direction)`,
`remainingPct = |price − liquidationPrice| / |entryPrice − liquidationPrice|`. Если по каким-то
причинам `btcReferencePrice()` недоступен/не отвечает на конкретном тике — шкала/тикер просто не
обновляется до следующего успешного тика (не ошибка на экран), статичные цены входа/ликвидации
показываются как сейчас, countdown и раскрытие позиций (§3 ниже) не зависят от этого вызова и не
блокируются.

## 3. Round-start reveal (D-22)

Мгновение, когда `phase` переключается `BETTING → RUNNING` и сервер впервые раскрывает
направления/суммы/позицию толпы. Один короткий, не тирированный (одна интенсивность) beat —
не путать с `result-moment.md`, это не итог, это «карты открыты»:

| t, ms | Что происходит |
|---|---|
| 0 | Диф зафиксировал переход фазы (тот же поллинг, что и `home()`/`round()`) |
| 0–400 | Карточка «{N} players have voted» делает 3D `rotateY` flip (`--ease-out-expo`, 400ms) — на обратной стороне уже отрисован результат раскрытия |
| 100–500 (внутри flip) | Позиции игроков появляются в свои панели (UP слева/зелёный wash, DOWN справа/красный wash — `direction.md` §4 «Stage/split-camp») каскадом, шаг 30–50ms на игрока, каждая — `opacity 0→1` + `translateY(8px→0)` |
| 0–400, синхронно | Карточка позиции толпы делает тот же flip, показывая направление/плечо/маржу/вход/ликвидацию |
| 400+ | Countdown на карточке переключается с «Closes in» на «Resolves in {mm:ss}» к `window.endMs`, без отдельной анимации — просто новый текст, момент раскрытия уже отыгран флипом |

`prefers-reduced-motion`: flip заменяется на простой fade (200ms), каскад позиций — без
`translateY`, только `opacity`.

## 4. Countdown — последние 10 секунд

Общий `Countdown` (`web/src/components/Common.tsx`) остаётся спокойным `tabular-nums` текстом,
пока не осталось ≤10с — тогда:

| Порог | Размер | Цвет | Поведение |
|---|---|---|---|
| > 10s | `--num-md` | `--text` | статично |
| ≤ 10s | плавный переход к `--num-lg`/`--num-xl-mobile` за 200ms | переход `--text → --warning` | на каждой секундной границе — `scale(1→1.06→1)`, 150ms |
| ≤ 3s | без изменения размера дальше | переход `--warning → --loss-neon` | тот же посекундный pulse + Light impact haptic на каждую секунду (3 тика максимум — не «зуммер») |

Это реальный, существующий в продукте таймер (закрытие ставок / резолв раунда) — эскалация его
подачи не создаёт нового давления, только честно отражает то, что уже происходит (не путать с
запрещённым «искусственным таймером давления», `game-designer.md`, «Честность» — там речь о
фальшивых/выдуманных таймерах, этот — настоящий).

## 5. Crowd-vs-market chart reacting

Лёгкое усиление `CrowdChart.tsx`/`StatTile`, не «слот-машина» — эта страница остаётся спокойнее,
чем момент итога:

- Новая точка (`CrowdHistoryPointDto`) на графике при обновлении истории появляется с коротким
  `scale(0→1)` поп-эффектом на самой правой точке линии (200ms, `--ease-out-back`), а не просто
  перерисовывается вместе со всей линией.
- Стат-плитки «Capital» / «This season» на `Crowd`/`Home` коротко (~400ms) прокручивают новое
  значение через `RollingDigits` (тот же компонент, что момент итога, без частиц/haptics/звука —
  только цифры) и на 1 цикл вспыхивают рамкой `--win-neon`/`--loss-neon` по знаку изменения,
  когда значение меняется между поллингами.
- Линия «толпа» (`COLOR_CROWD`) получает мягкое `filter: drop-shadow(0 0 6px var(--accent))` —
  постоянное, не анимированное — и полупрозрачную заливку области под собой (`<Area>` вместо
  голой `<Line>` для этой одной серии, две остальные — без заливки, чтобы не перегружать график).
