# UX-спецификация фронтенда

Дата: 2026-09-25. Статус: **спецификация для реализации, ни один экран не построен** — фронт
разрабатывается параллельно с бэкендом на тестовых данных по контракту API (Р-35), сейчас
готовится именно этот контракт (`web/src/api/contract.ts`) и то, как он ложится на экраны
(этот файл). Все факты о механике — со ссылкой на `docs/product/decisions.md` (Р-N) или
Java-код `engine/`; технические решения, которых нет ни в одном источнике (маршруты, состав
экранов сверх того, что фиксирует Р-34, разбивка на компоненты, точные тексты копирайта), помечены
как **предложение** — сама механика игры ими не меняется.

Источники (по порядку использования): `docs/product/decisions.md` (Р-1…Р-35, приоритет 1 при
расхождении), `docs/product/ux_walkthrough.md` (16 нерешённых UX-вопросов, часть закрывается
ниже), `docs/research/round_engine_design.md` и `engine/src/main/java/crowdvsmarket/engine/**`
(доменная модель, которую бэкенд обязан отдать через API), `docs/research/week1_wallet_auth.md`
(вход подписью кошелька), `docs/product/glossary.md` (термины). Копирайт интерфейса — на
английском (Р-24), везде ниже дан **точной цитатой** в кавычках; проза спецификации — на русском.

---

## 0. Общие принципы, зафиксированные Р-33/Р-34

- **Стиль — «игра», не биржевой терминал** (Р-33): крупные кнопки UP/DOWN, яркие цвета по
  направлению (зелёный/красный — предложение, ничего лучше не зафиксировано), таймер обратного
  отсчёта на видном месте, минимум терминов без пояснения.
- **Цена ликвидации видна до ставки** (Р-7, Р-33) — не после промежуточного шага, см. §11 и
  ответ на вопрос 3 в §12.
- **Главный экран** — фиксированная раскладка Р-34: сверху открытый для ставок раунд со ставкой,
  ниже график «толпа vs BTC vs анти-толпа», под ним топ рейтингов сезона; на телефоне без
  кошелька — график первым.
- **Публичные страницы — просмотр с телефона, ставки только с десктопа (Sage)** (Р-31): счёт
  толпы, рейтинги, профили. Считаю тем же классом «публичная страница» также «Как это работает»
  (чисто информационная, не требует кошелька) и сам Round-экран **после** раскрытия (Р-22) — его
  содержимое к этому моменту такое же публичное, как счёт толпы; обоснование — вывод не из
  Р-31 дословно, а из общего принципа, которым Р-31 мотивирована («просмотр без кошелька»), с
  этим согласуется. Экран Wallet и активный (не раскрытый) бет-слип — desktop-only целиком: там
  нет смысла в mobile-версии без подписи Sage.
- **Кошелёк сейчас — мок.** Реальный WalletConnect-вход требует Reown `projectId`, которого
  Алекс ещё не зарегистрировал (`docs/research/week1_wallet_auth.md` §1.2, §5) — так что за
  `Api.authChallenge`/`authVerify` (`web/src/api/contract.ts`) первое время стоит мок, который
  генерирует тестовый адрес и подпись локально вместо вызова Sage. Копирайт экранов ниже
  рассчитан на реальный флоу без изменений — переключение мок→реальный кошелёк меняет только
  реализацию `Api`, не один текстовый экран (ради этого контракт и существует). Единственная
  честная маркировка мок-режима — общий баннер «Demo data» (§2), а не подмена текста кнопки
  входа.

## 1. Информационная архитектура и маршруты

Предложение — ни один источник не фиксирует URL-схему, только состав экранов.

| Маршрут | Экран | Публичный/desktop-only | Требует кошелёк |
|---|---|---|---|
| `/` | Home | публичный (Р-31-класс) | нет для просмотра, да для ставки |
| `/round/:roundId` | Round | публичный после раскрытия (Р-22); бет-слип — desktop-only | нет для просмотра, да для ставки |
| `/crowd` | Crowd | публичный (Р-31) | нет |
| `/ratings` | Ratings | публичный (Р-31) | нет |
| `/profile/:playerId` | Profile (чужой) | публичный (Р-31) | нет |
| `/profile/me` | Profile (свой) | требует сессии | да |
| `/wallet` | Wallet | desktop-only целиком | да |
| `/how-it-works` | How it works | публичный | нет |

Общий header/nav на каждом экране (desktop): логотип-название, ссылки Home / Crowd / Ratings /
How it works, справа — баланс PLAY (если вошёл) или кнопка входа, справа профиль-меню (ник +
сокращённый адрес, ссылка «My profile», «Wallet», «Sign out»). На mobile — компактный header без
баланса/входа на публичных экранах (там нет кошелька, Р-31), с гамбургер-меню на Home / Crowd /
Ratings / How it works.

## 2. Общие элементы

### Баннер «Demo data»

Требование задачи: пока приложение работает на моковых данных, честный баннер обязателен, без
исключений и без мелкого шрифта. Закреплённая полоса под header, на каждом экране, не
закрываемая:

> **"DEMO — PLAY is toy money on a test network. Nothing here is real funds."**

### Про управляемый оракул (закрывает вопрос 9 из `ux_walkthrough.md`)

Не прячем в одном FAQ — показываем короткой строкой везде, где от оракула зависит исход:

- Round-экран, в состояниях RUNNING/SETTLED, под ценой: **"Price from Hyperliquid, published by our team's key — not a decentralized oracle."**
- Crowd-экран, под графиком: та же строка.
- Полное объяснение — на `/how-it-works`.

### Про отсутствие защиты от мультиаккаунтов (закрывает вопрос 16)

Показываем не только в FAQ (`docs/product/faq.md`), но и там, где новичок реально смотрит:

- На экране выбора ника при первом входе (§10, шаг 2), мелкая строка под полем:
  **"Ratings are for fun — we don't detect multiple accounts."**
- На Ratings-экране, под заголовком: та же строка.

### Общие паттерны состояний

- **Loading** — скелетоны в форме итогового контента (карточки/строки-заглушки с анимацией
  пульсации), не спиннер на весь экран, кроме первой загрузки всего приложения (там — спиннер +
  название продукта).
- **Error** (сетевая/серверная ошибка, не доменная) — карточка по центру области:
  иконка, **"Something went wrong."**, кнопка **"Try again"**. Текст ошибки от сервера никогда не
  показывается как есть (закрывает вопрос 8) — только маппинг `ApiErrorCode` →
  человекочитаемый текст, заданный на экране, где ошибка возникла (см. §4 для бет-слипа).
- **Empty** — свой текст на каждом экране (см. ниже), без общей заглушки.

## 3. Экран Home (`/`)

### Назначение

Единственная точка входа новичка и ежедневная точка входа игрока: увидеть открытый раунд, сделать
ставку, увидеть, куда движется толпа, и своё место в рейтинге — одним взглядом (Р-34).

### Desktop-раскладка

Сверху вниз, одна колонка на всю ширину с внутренними двух-трёх-колоночными блоками:

1. **Переключатель Hourly / Daily** (таб-бар) — определяет, какая пара раундов показана ниже.
2. **Блок открытого раунда** — двухколоночный: слева статус текущего идущего раунда (только
   индикатор + таймер + краткий итог, ссылка на полный Round-экран), справа — бет-слип на раунд,
   открытый для ставок (полная копия §11, встроенная прямо на Home — Р-34 требует бет-слип на
   главном экране, не только на Round-экране).
3. **График «толпа vs BTC vs анти-толпа»** (Р-17, Р-25, Р-26) — на всю ширину, компактная версия
   (последние ~90 дней с возможностью переключить на «весь период»); ссылка **"Full crowd account →"**
   на `/crowd`.
4. **Топ рейтингов** — двухколоночный: слева топ-5 **"Richest"**, справа топ-5 **"Prophets"**,
   каждый со ссылкой **"Full ratings →"** на `/ratings`.

### Mobile-раскладка (просмотр без кошелька, Р-31/Р-34)

Порядок иной — график первым (Р-34 буквально): 1) график, компактный, без переключателя таймфрейма
бет-слипа; 2) карточка открытого раунда — статус и таймер, **read-only**, кнопка
**"Open on desktop to bet"** вместо бет-слипа (десктоп-only ставки, Р-31); 3) топ рейтингов, в одну
колонку, сначала Richest, затем Prophets.

### Компоненты

`IntervalTabs`, `RoundStatusCard`, `BetSlip` (см. §11), `CrowdChartCompact`, `RatingsTopList`.

### Состояния

- **Loading** — скелетоны всех четырёх блоков одновременно (параллельные запросы к `home()`).
- **Error** — общий паттерн §2 на весь экран, если `home()` целиком не отвечает; если отвечает
  частично — соответствующий блок показывает свою мини-ошибку (**"Couldn't load the chart."** и т.п.)
  без блокировки остальных.
- **Not signed in** — бет-слип на Home заменяется карточкой призыва:
  заголовок **"Connect your wallet to place a bet"**, кнопка **"CONNECT WALLET"** (открывает
  флоу §10 шаг 1); сам раунд, счёт голосов (только количество, Р-22) и график остаются видны без
  входа — просмотр публичен.
- Остальные состояния бет-слипа (below min stake, insufficient balance, already bet →
  edit/cancel, betting closed) — идентичны §11, встроенная копия того же компонента.

### Копирайт

- Заголовок таб-бара: **"Hourly"** / **"Daily"**.
- Заголовок карточки раунда: **"Current round"**.
- Заголовок графика: **"Crowd account vs BTC"**.
- Заголовки списков рейтинга: **"Richest"**, **"Prophets"**.
- Пустой топ рейтинга (никто ещё не прошёл порог, см. §12 вопрос 10):
  **"No one has qualified yet — play {N} rounds this season to appear here."**
  (`{N}` = `RatingsDto.roundsThreshold`, сейчас 10 — Р-28).

## 4. Экран Round (`/round/:roundId`)

### Назначение

Полная картина одного раунда: пока идут ставки — бет-слип и счётчик участников (Р-22); после
старта — раскрытые позиции всех игроков и позиция счёта толпы; после закрытия — итог; при
отмене — причина.

### Desktop-раскладка

Двухколоночная: слева — цена/таймер/статус-бейдж и (в фазе BETTING) бет-слип §11 или (после
раскрытия) список позиций толпы с направлением/плечом/итогом каждой, справа — карточка позиции
счёта толпы (то же, что на публичной Crowd-странице, но только по этому раунду) и, если раунд уже
разрешился, разбор: цена открытия/закрытия, кто выиграл/проиграл, изменение баланса игрока (если
он участвовал).

### Mobile-раскладка

Одна колонка сверху вниз: статус-бейдж/таймер → (если BETTING) заглушка **"Open on desktop to bet"**
вместо бет-слипа, но счётчик участников виден → позиция толпы → список позиций игроков (после
раскрытия) в виде компактных строк, без интерактива.

### Компоненты

`RoundStatusBadge` (см. значения ниже), `Countdown`, `BetSlip` (§11), `ParticipantCount`,
`PositionsList`, `CrowdPositionCard`, `CancellationNotice`.

### Состояния (все обязательные для этого экрана)

- **Loading** — скелетон статус-бейджа + пустые карточки.
- **Error** — общий паттерн §2, кнопка **"Try again"**.
- **Betting open** (`phase: "BETTING"`) — бейдж **"OPEN FOR BETS"** (жёлтый/синий — предложение),
  таймер **"Closes in {mm:ss}"**, строка **"{N} players have voted"** (только число, Р-22),
  бет-слип §11 или заглушка «Not signed in» / «already bet» ниже.
- **Round running** (`phase: "RUNNING"`) — бейдж **"LIVE"** (красный, пульсирующий), таймер
  **"Resolves in {mm:ss}"**, цена открытия, список раскрытых позиций (направление, плечо, ник),
  карточка толпы с направлением/плечом/маржой/ценой входа/ценой ликвидации. Строка честности про
  оракул (§2).
- **Liquidated** (своя позиция, в списке позиций или в персональной плашке сверху, если это
  позиция вошедшего игрока) — красная плашка: **"LIQUIDATED — you lost your whole stake."** (Р-7).
  То же для позиции толпы отдельной плашкой: **"Crowd account liquidated this round."**
- **Settled** (`phase: "SETTLED"`) — бейдж **"SETTLED"**, заголовок
  **"BTC closed {UP/DOWN} — {open} → {close}"**, для своей позиции (если участвовал) —
  **"You won {payout} PLAY"** / **"You lost your stake"** / **"Liquidated — stake lost."**, для
  каждой публичной позиции — итог (won/lost/liquidated), карточка толпы с итоговым капиталом
  до/после.
- **Cancelled with reason** (`phase: "CANCELLED"`) — бейдж **"CANCELLED"** (серый), карточка:
  **"This round was cancelled."**, ниже точная причина из `CancellationDto.reason` **как есть,
  без перевода/перефразирования** (публичная прозрачность, Р-32), строка
  **"All {N} bets were refunded, including any that would have been liquidated."** (Р-23).
- **Not signed in** (во время BETTING) — вместо бет-слипа карточка: заголовок
  **"Connect your wallet to place a bet"**, текст **"You can still watch this round without one."**,
  кнопка **"CONNECT WALLET"**.
- **Insufficient balance** (при попытке поставить) — под полем стейка:
  **"Not enough PLAY — you have {balance} PLAY, this bet needs {stake} PLAY."**, кнопка
  подтверждения задизейблена.
- **Below min stake** — под полем стейка: **"Minimum stake is 100 PLAY."**, кнопка задизейблена.
- **Already bet this round → edit/cancel** — бет-слип заменяется карточкой текущей ставки:
  **"Your bet: {UP/DOWN} · x{leverage} · {stake} PLAY"**, две кнопки: **"EDIT BET"** (открывает
  тот же бет-слип, предзаполненный) и **"CANCEL BET"** (после подтверждающего диалога
  **"Cancel your bet and get {stake} PLAY back?"** / **"KEEP BET"** / **"CANCEL BET"**).

### Копирайт (сводка новых строк, не повторяющихся выше)

- `RoundStatusBadge` значения: **"OPEN FOR BETS"**, **"LIVE"**, **"SETTLED"**, **"CANCELLED"**.
- Заголовок карточки толпы: **"Crowd account's position"**.
- Заголовок списка позиций: **"All positions"**.

## 5. Экран Crowd (`/crowd`)

### Назначение

Публичная витрина «толпа против рынка» (Р-5, Р-14, Р-17, Р-25, Р-26) — главный демонстрационный
экран продукта, честный и читаемый без входа.

### Desktop-раскладка

Заголовок **"Crowd account vs the market"**, под ним три статистики в ряд: текущий капитал счёта
толпы, доходность с начала (в % от $100 000), доходность текущего сезона (Р-25 — «рядом
доходность за каждый сезон», реализовано как отдельная плашка). Ниже — полноразмерный график трёх
линий (crowd / BTC hold / anti-crowd) на всю ширину, с легендой и переключателем диапазона
(1M/3M/1Y/All), с отметками границ сезонов на оси (Р-25). Под графиком — таблица сезонной
доходности (`SeasonReturnDto[]`, все сезоны). Строка честности про оракул (§2) под графиком.

### Mobile-раскладка (Р-31 — просмотр)

То же по составу, в одну колонку: три статистики стопкой, затем график (адаптированная ширина,
тот же переключатель диапазона тапами), затем таблица сезонов.

### Компоненты

`StatTile` × 3, `CrowdChart` (три серии), `SeasonReturnsTable`.

### Состояния

- **Loading** — скелетоны трёх плашек + скелетон графика (пустой прямоугольник с пульсацией).
- **Error** — общий паттерн §2.
- **Empty** (гипотетический — капитал есть с самого первого дня, Р-25, так что `history` пустым
  быть не должно после первого сыгранного раунда; до первого раунда) —
  **"The crowd account opens its first position when the first round settles."**

### Копирайт

- Плашки: **"Capital"**, **"Return since day one"**, **"This season"**.
- Легенда графика: **"Crowd account"**, **"Hold BTC"**, **"Anti-crowd"**.
- Заголовок таблицы: **"Season returns"**.

## 6. Экран Ratings (`/ratings`)

### Назначение

Два сезонных рейтинга (Р-18, Р-28, Р-30): **"Richest"** (прирост баланса) и **"Prophets"** (доля
угаданных направлений).

### Desktop-раскладка

Таб-бар **"Richest"** / **"Prophets"** сверху (или две колонки бок о бок — предложение: таб-бар
проще для длинных списков и одинаково работает на mobile). Под табами — переключатель сезона
(текущий по умолчанию, выпадающий список прошлых сезонов — Р-10 «прошлые сезоны — в архиве»).
Таблица: ранг, ник+адрес (кликабельно → `/profile/:id`), значение метрики, число сыгранных
раундов. Дисклеймер про отсутствие защиты от мультиаккаунтов (§2) под заголовком.

### Mobile-раскладка

То же, список карточек вместо табличных строк (ранг + ник + значение + раунды), тот же таб-бар и
переключатель сезона.

### Компоненты

`RatingsTabs`, `SeasonPicker`, `RatingsTable` (или `RatingsList` на mobile).

### Состояния

- **Loading** — скелетон 10 строк.
- **Error** — общий паттерн §2.
- **Empty** — **"No one has qualified yet — play {N} rounds this season to appear here."**
  (тот же текст, что на Home, `{N}` = `roundsThreshold`).
- **Below threshold (свой ник)** — если вошедший игрок сыграл меньше `roundsThreshold` раундов, в
  шапке экрана — плашка: **"Play {K} more rounds this season to appear in the ratings."**
  (`K = roundsThreshold - roundsPlayed`), где `roundsPlayed` — из `mySeasonRecord()`. Закрывает
  часть вопроса 10 (§12): ник **не** виден в списке до порога, но узнаёт, сколько ещё нужно.

## 7. Экран Profile (`/profile/:playerId`, `/profile/me`)

### Назначение

Публичный профиль (Р-29): ник + сокращённый адрес, история прошлых раундов (направление, плечо,
итог); текущая ставка — не показывается никогда, даже владельцу на этом экране (скрыта до старта,
Р-22 — для своей текущей ставки использовать Home/Round, не Profile).

### Desktop-раскладка

Заголовок — `displayName` крупно, под ним (если есть) сезонная статистика (`SeasonRecordDto`):
сыграно раундов, доля угаданных направлений, прирост баланса за сезон. Ниже — таблица истории

## 8. Экран Wallet (`/wallet`)

### Назначение

Единственный экран, где происходят подписываемые Sage действия: вход, баланс, вывод PLAY в

Сверху — баланс крупно (**"{balance} PLAY"**), под ним — история движений баланса

`BalanceHeader`, `LedgerHistoryList`, `WithdrawForm`, `DepositForm`.

### Состояния

- **Not signed in** — вместо всего экрана: карточка **"Connect your wallet to see your balance"**,
  кнопка **"CONNECT WALLET"** (запускает флоу §10 шаг 1).
- **Loading** — скелетон баланса + скелетон истории.
- **Error** — общий паттерн §2.
- **Empty** (история) — **"No activity yet — your starter pack will appear here once you sign in."**
  (в норме невозможно: `ensureSeasonPack` начисляет пакет сразу при первой активности, но текст
  нужен на случай гонки загрузки).
- **Withdrawal below balance / above balance** — то же правило валидации, что у ставки:
  **"You only have {balance} PLAY."**, кнопка задизейблена.

  при **CONFIRMED** — **"Deposit confirmed — {amount} PLAY added to your balance."**; при
  **FAILED** — **"Deposit failed — no PLAY was received."**

## 10. Первый вход (first-time flow)

Шаги, экран за экраном, с точным копирайтом. Источники: Р-2, Р-4, Р-12, Р-15,
`docs/research/week1_wallet_auth.md` §4.

**Шаг 0 — старт.** Новичок на Home видит продукт без входа (просмотр публичен), жмёт
**"CONNECT WALLET"** в header или в любой карточке-приглашении.

**Шаг 1 — подключение кошелька.** Модальное окно: заголовок **"Connect your wallet"**, текст
**"We'll ask Sage to sign a short message — this does not move any funds."** (закрывает часть
вопроса 1 из §12 — что происходит и что это не транзакция), кнопка **"Continue with Sage"**.
По клику — запрос challenge (`authChallenge`), затем запрос подписи у кошелька (в реальном флоу —
Sage-модалка с `message` из ответа, видимая пользователю **до** подтверждения — это и есть тот
единственный момент, где Sage не может сама объяснить, что подписывается, поэтому наш экран
показывает точный текст заранее, самим текстом challenge-сообщения, не полагаясь на Sage; в
mock-режиме — мгновенная имитация без реального диалога). Состояние ожидания:
**"Waiting for confirmation in Sage…"** со спиннером.

**Шаг 2 — выбор ника** (только если `AuthSessionDto.isNewPlayer === true`, Р-15). Экран:
заголовок **"Pick a nickname"**, текст **"Shown next to your wallet address — {shortAddress}."**,
поле ввода, мелкая строка (§2) **"Ratings are for fun — we don't detect multiple accounts."**,
кнопка **"CONTINUE"** (задизейблена, пока поле пусто).

**Шаг 3 — стартовый пакет.** Экран-подтверждение: крупно **"You've got 10,000 PLAY"**, ниже
**"Toy money for this demo — place your first bet or explore the crowd account."**, две кнопки:
**"PLACE A BET"** (ведёт на Home/Round с открытым бет-слипом) и **"EXPLORE"** (закрывает модалку,
остаётся на текущей странице). Начисление уже произошло на бэкенде при первой активности
(`ensureSeasonPack`, движок) — этот экран только показывает свершившийся факт, не отдельный шаг
запроса.

**Шаг 4 — первая ставка.** Открывается бет-слип §11, предзаполненный ничем (чистая форма);
дальше — обычный путь ставки.

## 11. Bet slip — детальная спецификация

Используется на Home (встроенно) и на Round (полноразмерно) — один и тот же компонент.

### Поля и порядок (сверху вниз)

1. **Direction** — две крупные кнопки на всю ширину, **"UP"** (зелёная) / **"DOWN"** (красная)
   (Р-33). Ровно одна выбрана в любой момент.
2. **Leverage** — слайдер, диапазон `LEVERAGE_MIN..LEVERAGE_MAX` (2..40, `contract.ts`),
   целочисленный шаг 1, подпись над слайдером **"Leverage: x{value}"**, обновляется вживую при
   перетаскивании.
3. **Stake** — числовое поле, подпись **"Stake (PLAY)"**, под полем — быстрые кнопки
   **"MIN"** (100), **"25%"**, **"50%"**, **"MAX"** (от текущего баланса, доступны только вошедшим
   игрокам).
4. **Liquidation preview** — карточка, обновляется при каждом изменении direction/leverage/stake
   (дебаунс ~150мс, без отдельной кнопки «посчитать» — закрывает вопрос 3 в §12):
   - **"Liquidation price: ${liquidationPrice}"**
   - **"{percentToLiquidation}% move to liquidation"**
   - мелким текстом под карточкой: **"Estimated from the current price — your real entry price is set when the round starts."**
     (честность про разницу preview/реальной цены входа, см. `MarketReferenceDto` в контракте).
5. **Submit** — кнопка **"PLACE BET"** (или **"UPDATE BET"** в режиме редактирования, §4).

### Валидация (клиентская — зеркалит `LedgerBook`/`Leverage` на сервере, контракт §"Engine constants")

- `stake < MIN_STAKE_PLAY` (100 PLAY) → кнопка задизейблена, текст **"Minimum stake is 100 PLAY."**
- `stake > текущий баланс` → кнопка задизейблена, текст
  **"Not enough PLAY — you have {balance} PLAY, this bet needs {stake} PLAY."**
- `leverage` вне 2..40 — недостижимо через слайдер (границы слайдера сами это гарантируют).
- Оба нарушения проверяются заново сервером при отправке (`STAKE_BELOW_MINIMUM`,
  `INSUFFICIENT_BALANCE` из `ApiErrorCode`) — клиентская проверка не единственная линия защиты,
  только для мгновенной обратной связи.

### Режим редактирования («already bet this round»)

Форма предзаполняется текущей ставкой (`RoundBetting.myBet`), кнопка — **"UPDATE BET"**, рядом —
вторичная кнопка **"CANCEL BET"** (см. диалог подтверждения в §4). Отправка `placeBet` с тем же
`roundId` заменяет старую ставку (Р-13, `GameEngine.placeBet`) — отдельного «шага подтверждения
замены» не показываем, серверная семантика уже безопасна (сначала возврат старой, потом резерв
новой).

### Закрытие окна ставок во время заполнения формы

Если `phase` раунда переключился с `BETTING` на `RUNNING`, пока форма открыта (таймер дошёл до
нуля) — форма блокируется немедленно (без ожидания ответа сервера на возможный поздний submit),
показывается: **"Betting just closed for this round."**, кнопка **"View next round"** ведёт на
следующий открытый раунд той же серии.

## 12. Ответы на UX-вопросы (`docs/product/ux_walkthrough.md`)

Нумерация — как в исходном файле.

1. **Онбординг без кошелька.** Отвечено (§10): шаг встроен в сам продукт (модалка при клике
   «Connect wallet» с объяснением, что происходит), не только внешний README.
2. **Первые PLAY** — решено Р-2/Р-4/Р-12, экран подтверждения — §10 шаг 3.
3. **Когда показывается цена ликвидации.** Отвечено (§11): статический калькулятор, мгновенный
   пересчёт при каждом изменении полей, без промежуточного шага/черновика Offer.
4. **Экранное представление голоса** — отвечено §4 (счётчик участников в BETTING, раскрытые
   позиции в RUNNING/SETTLED).
5. **Экранное представление позиции толпы** — отвечено §4/§5 (карточка толпы на Round и на
   Crowd).
6. **Текст/индикатор резолва + хранение истории.** Отвечено: индикатор — статус-бейдж **"SETTLED"**
   + разбор итога на Round (§4); хранение истории — `ProfileRoundEntryDto[]`, экран Profile (§7).
7. **Задержка публичной страницы счёта толпы относительно оракула.** Предложение (не решение
   механики игры, а архитектурный выбор для недели реализации): поллинг, не WebSocket — проще
   для MVP без выделенной инфраструктуры; страница показывает **"Updated {HH:MM:SS} UTC"** рядом
   с ценой/капиталом, чтобы разрыв был явным, а не молчаливым. Финальный интервал поллинга — не
   зафиксирован, решить в неделю реализации Round-экрана.
8. **Ошибки транзакций понятным языком.** Отвечено: `ApiErrorCode` → человекочитаемый маппинг
   (§2, §4, §8), сырой текст ошибки Sage/сервера никогда не показывается.
9. **Где написано про управляемый оракул.** Отвечено (§2, §4, §5, §9) — на каждом экране, где
   от него зависит исход, не только в FAQ.
10. **Виден ли новичок в рейтинге до порога N.** Отвечено (§6): не виден в списке, но видит
    **"Play {K} more rounds…"**. Само число N зафиксировано Р-28 = 10.
11. **Баланс PLAY в реальном времени.** Отвечено: header показывает баланс постоянно (вошедшим
    игрокам), Wallet — полную историю движений (§8); отдельный block explorer не нужен для этого.
12. **Доступность без десктопа.** Решено Р-31: публичные страницы — да, просмотр; ставки — нет.
13. **Два раунда одного типа одновременно.** Отвечено (§3, §4): раздельные статус-бейджи
    **"OPEN FOR BETS"** vs **"LIVE"**, на Home бет-слип явно привязан к карточке открытого (не
    идущего) раунда самим расположением (бет-слип рядом со статусом именно открытого раунда, не
    общий на оба).
14. **Экран вывода/возврата PLAY.** Отвечено предложением (§8, Wallet, Deposit) — ручное
    «я отправил, вот подтверждение» (текстовое поле, без автоматического сканирования адреса в
    MVP, поскольку `OnChainWalletPort` не реализован — вне скоупа движка, round_engine_design.md
    §2). Статусные тексты между отправкой и зачислением — там же.
15. **Поиск контрагента для Offer-обмена.** Отвечено предложением: **вне продукта в MVP** —
    никакой встроенной доски объявлений; продукт из этого файла не порождает интерфейс для
    Offer-обмена между игроками вовсе (не входит ни в один экран §3–9). Обоснование: Р-6
    фиксирует сам механизм (Offer), не обязанность продукта его опосредовать; экономия объёма
    MVP. Решить окончательно с Алексом до недели, где Offer-обмен берётся в работу.
16. **Раскрытие «мультиаккаунты не отслеживаются».** Отвечено (§2, §6, §10 шаг 2) — на экране
    выбора ника, на Ratings, не только в FAQ.
