## 0. Общие принципы, зафиксированные Р-33/Р-34

- **Стиль — «игра», не биржевой терминал** (Р-33): крупные кнопки UP/DOWN, яркие цвета по
  направлению (зелёный/красный — предложение, ничего лучше не зафиксировано), таймер обратного
  отсчёта на видном месте, минимум терминов без пояснения.
- **Цена ликвидации видна до ставки** (Р-7, Р-33) — не после промежуточного шага, см. §11 и
  ответ на вопрос 3 в §12.
- **Главный экран** — фиксированная раскладка Р-34: сверху открытый для ставок раунд со ставкой,
  ниже график «толпа vs BTC vs анти-толпа», под ним топ рейтингов сезона — тот же порядок на
  любой ширине экрана (см. ниже, Р-48 отменяет прежний мобильный частный случай).
- **Ставки и кошелёк работают с телефона целиком** (Р-48, **заменяет Р-31**): все публичные
  экраны (счёт толпы, рейтинги, профили, Round после раскрытия Р-22, «Как это работает») и сам
  бет-слип/Wallet одинаково полнофункциональны на desktop и на mobile (375px). Прежнее деление
  «просмотр на телефоне, ставки только с десктопа (Sage)» снято — обоснование прежнего деления
  (Sage = desktop-only) само оказалось ошибочным: у Sage есть мобильные сборки (Р-48). Плюс —
  PWA: манифест (иконка «Herd» на экране), service worker кеширует только статическую оболочку
  приложения (never `/api/`). **Правка 2026-09-26**: сам билд для Docker/web-стенда собирается с
  АБСОЛЮТНЫМИ путями (`vite.config.ts`'s `base: "/"`) — относительные пути ломали прямой
  заход/обновление вложенного маршрута (например `/round/<id>`): SPA-fallback nginx отдаёт тот же
  `index.html`, а относительный `./assets/...` резолвился уже от `/round/`, не от корня → пустой
  экран. Относительные пути (`base: "./"`, `CAPACITOR_BUILD=1 npm run build:capacitor`) остаются
  только для будущего Capacitor-билда, который бандлит `dist/` как локальные `file://`-ассеты —
  сегодняшний Capacitor-билд грузит тот же живой URL стенда, что и браузер, и этой правкой не
  затронут.
- **Кошелёк на локальном стенде — настоящий тестовый, не мок (Р-44/Р-45).** Для локального
  Docker-стенда на Atlas каждое окно/вкладка/профиль браузера генерирует свой настоящий
  Chia-ключ (`chia-wallet-sdk-wasm`) и подписывает вход по той же схеме, что и Sage
  (`docs/research/week1_wallet_auth.md` §2) — это не имитация подписи, а реальная BLS-подпись,
  просто без внешнего приложения-кошелька. Экран входа честно называет это «Test wallet»
  (см. §10 шаг 1). **Правка 2026-09-26 (Р-55):** реальный вход через Sage/WalletConnect
  реализован (`web/src/wallet/walletConnect.ts`, §10 шаг 1a) и стоит рядом с тестовым кошельком
  на том же экране — но Alex ещё не зарегистрировал Reown `projectId`
  (`week1_wallet_auth.md` §1.2, §5, «Реализация»), поэтому кнопка **"Connect with Sage"** пока
  задизейблена («Coming soon…», §10 шаг 1) везде, где это не исправлено отдельной сборочной
  переменной или полем `serverInfo`. Копирайт экранов ниже рассчитан на оба флоу без изменений —
  ни тестовый кошелёк, ни Sage не меняют один текстовый экран, только реализацию (ради этого
  контракт и существует). Единственная честная маркировка demo/mock-режима — общий баннер «Demo
  data» (§2), а не подмена текста кнопки входа.
- **Статус сервера виден, не спрятан.** Когда `Api.serverInfo()` существует (реальный бэкенд,
  `RealApi`) — на каждом экране небольшой баннер в тестовом режиме («Replay: BTC prices from
  …–…, N× speed»), бейдж **BOT** у каждого игрока-бота (Р-46) везде, где показан игрок,
  строка статуса оракула (последний подтверждённый seq/height на testnet11) на Crowd-экране,
  и хеш итогов + ссылка на `results.json` на разрешённом/отменённом Round-экране (Р-41). У
  `MockApi` этого метода нет вовсе — соответствующие элементы UI просто не рендерятся, это не
  ошибка загрузки.
- **Аппаратная кнопка «Назад» на Android не выходит из приложения** (добавлено 2026-09-26,
  player-review fix item 4) — по умолчанию Capacitor закрывает приложение на любое нажатие
  системной кнопки «Назад», которое ничем не обработано; это ощущалось как краш/выход прямо из
  комнаты пары (`/play/:marketId`, до 2026-10-02 `/play/:asset`), хотя внутри приложения было куда возвращаться (Lobby → Pair
  room). `web/src/fx/useAndroidBackButton.ts` (`@capacitor/app`'s `backButton`, только нативная
  сборка — на web/PWA работает обычный Back браузера) переходит на один шаг назад по истории, пока
  есть куда, и только с Lobby (`/`) — приложение действительно один корневой экран (Р-59/Р-61) —
  отдаёт нажатие системе (выход).

## 1. Информационная архитектура и маршруты

**Переписано 2026-09-26 (концепция A, Р-61/Р-59)** — заменяет всю прежнюю раскладку («Home с
графиком и рейтингами на главном») на «лобби с плитками пар → комната пары → статистика отдельной
вкладкой», буквально то, что описал Алекс в Р-59. Маршруты — по-прежнему предложение (ни один
источник не фиксирует URL-схему), только состав экранов и порядок навигации теперь зафиксирован
Р-59/Р-61. **2026-10-02:** «плитки пар» лобби стали лентой категорий с карточками рынков (§3a,
Р-69), комната пары — `/play/:marketId` (§3b); состав вкладок и остальные маршруты не менялись.

|---|---|---|---|

| `/play/:marketId` | **Pair room** (§3b) — комната конкретного рынка (`BTC`, `xyz_NVDA`, `PM900104`; id без учёта регистра; `?side=up\|down` — предвыбранная сторона, `?series=daily` — длинная серия) | публичный для просмотра | да для ставки |
| `/round/:roundId` | Round (§4) — постоянная ссылка на конкретный (в т.ч. прошлый) раунд | публичный после раскрытия (Р-22 для чужих направлений; расклад UP/DOWN — вживую, Р-62) | нет для просмотра, да для ставки |

Старые маршруты не удалены, а редиректят на новую вкладку Stats (React Router `<Navigate replace>`,

**Правка 2026-09-26 (player-review fix item 2, «Profile» открывал кошелёк, не профиль).**
`/profile/me` больше не редиректит на сегмент History вкладки Stats — это теперь отдельный экран
`MyProfilePage.tsx`, тот самый, который открывает нижняя вкладка «Profile» (см. таб-панель ниже).
Внутри — тот же контент, что раньше показывал сегмент History (переиспользует `ProfilePage mine`
как есть, без дублирования — ник, аватар, сезонная статистика, история раундов), плюс
in-page под-вкладка **«Wallet»** (не отдельный маршрут — переключатель `useState`, как
`IntervalTabs`/Stats-табы), которая рендерит тот же `WalletContent`, что и раньше жил только на
`/wallet`. Маршрут `/wallet` не убран — работает как самостоятельная страница (шапка's пилюля
баланса, меню ника's пункт «Wallet», старые закладки) с тем же содержимым, ничего не потерял.
Сегмент History внутри Stats-вкладки (`/stats/history`) тоже никуда не делся — показывает тот же
`ProfilePage mine`, что и раньше; теперь это просто второй путь к тому же контенту, не единственный.

**Нижняя таб-панель (`web/src/components/Layout.tsx`'s `BottomTabBar`)** — главная навигация,
одна и та же на desktop и mobile (не два разных паттерна, как раньше top-nav+гамбургер): **Lobby**
(`/`) / **Stats** (`/stats`) / **Profile** (`/profile/me`, до правки 2026-09-26 выше вела на
`/wallet`). Верхний header упрощён до: логотип-ссылка на `/`, переключатель звука/вибрации, пилюля
баланса (если вошёл, по-прежнему ведёт на `/wallet` напрямую) или кнопка **CONNECT WALLET**, и
(вошедшим) компактное меню ника (My profile → `/profile/me` / Wallet → `/wallet` / Sign out) —
старые верхние ссылки Home/Crowd/Ratings/How it works убраны (Home = Lobby теперь и так первая
вкладка; How it works — ссылка в футере, `Layout.tsx`).

Ни один маршрут не desktop-only (Р-48 остаётся в силе) — «публичный / требует кошелёк» действует
на любой ширине экрана.

**Баланс PLAY = свободный + в игре** (usability-фикс 2026-09-25, отчёт Алекса: баланс в шапке
показывал только свободный остаток, поэтому игрок, только что выигравший раунд и тут же
поставивший на следующий, видел баланс *ниже* стартового пакета без единого пояснения). Пилюля
баланса — две строки: **"{balance} PLAY"** крупно, под ней (только если сумма > 0), мелким
приглушённым текстом — **"+{N} in play"**, где `{N}` — сумма ставок игрока во всех открытых для
ставок и идущих раундах обеих серий (Hourly + Daily): резерв на раунд в `BETTING`
(`RoundBetting.myBet.stake`) + позиция на раунде в `RUNNING` (`PublicPositionDto.stake` —
исключая раунды `SETTLED`/`CANCELLED`, чей результат уже начислен/возвращён). Источник данных —
существующий `rounds()` по обеим сериям, отдельного вызова к серверу не добавляет.

**Правка 2026-09-26 — единица измерения в самой пилюле стала icon-only.** На узком (1080px)
телефоне слово «PLAY» после числа переносилось на вторую строку самой пилюли (не путать со
второй строкой «+{N} in play» выше) — в шапке не хватало ширины после логотипа/FX-меню/профиль-
меню. В компактной шапочной пилюле теперь только число (**"{balance}"**), единицу называет золотая
монетка-иконка рядом с числом; слово «PLAY» остаётся текстом в `aria-label` пилюли (программа
чтения с экрана по-прежнему объявляет «Balance: {balance} PLAY») и никуда не убрано с более
просторных экранов — Wallet (§5), карточка момента итога (`result-moment.md`) показывают полное
«{amount} PLAY», как и раньше.

**Каркас телефона — правка 2026-10-02 (`docs/HANDOFF.md` §6 п. 9–10; `web/index.html`, `index.css`, `components/Layout.tsx`, `ScrollManager.tsx`).**

- **Вырез и индикатор «домой»**: страница открывается с `viewport-fit=cover`, шапка, нижняя таб-панель, поля контейнера, модалки и подвал учитывают `env(safe-area-inset-*)` (токены `--safe-top/right/bottom/left`, `--header-offset` = шапка + вырез; от него липнет лента категорий лобби). До этого шапка заходила под статус-бар. Попутно исправлена ошибка высоты нижней панели: фиксированная высота с `padding-bottom` сжимала иконки до 11 px на айфоне с индикатором; теперь высота панели `calc(var(--tabbar-height) + var(--safe-bottom))`. Проверено эмуляцией Chrome (`Emulation.setSafeAreaInsetsOverride`, 47/34 px); реальный iPhone и Android-эмуляторы в этом шаге не использовались.
- **Пилюля баланса** — сетка: монета слева на две строки, справа сумма, под ней **"+N in play"** (раньше монета, сумма и «+N in play» стояли в одну строку, и у вошедшего игрока с длинным ником шапка уходила за правый край 390 px). «In play» берётся из `myAccount().inPlay` по всем рынкам (`api/inPlay.ts`; суммирование `rounds()` — только запасной путь для сервера без поля).
- **Прокрутка при переходах** (`ScrollManager`): новый экран открывается сверху, Back возвращает на сохранённую позицию, замена адреса без смены пути (набор в поиске, чипы лобби) страницу не двигает. До этого `BrowserRouter` оставлял окно на месте: прокрутив лобби из 18 карточек и нажав на карточку, игрок попадал в комнату уже «пролистанной».
- **Полоса «Your bets»** (§3c) встроена в `Layout` над содержимым каждого экрана, не прижата к краю.

### Момент итога раунда (result moment) — глобальный, видим с любой страницы

Реализует Р-50/Р-51/Р-52 (`docs/product/design/result-moment.md`) — событие обнаруживается
независимо от того, какая страница открыта (свой поллинг `home()`, `web/src/fx/
useSettlementWatcher.ts`), и всплывает поверх текущего экрана:

- **WIN / LOSS / EVEN** (итог раунда по расчёту) — полноэкранный момент с затемнённой (но не
  непрозрачной) подложкой: заголовок — всегда подписанный чистый результат (`net = payout − stake`,
  никогда сумма выплаты), монеты/искры/конфетти (WIN) или осколки (LOSS) по канвасу, число крутится
  вверх/вниз, баланс в шапке считает синхронно. Тир интенсивности (T1–T4) — по множителю (WIN) или
  доле ставки от баланса (LOSS), точные таблицы — `result-moment.md` §2.
- **LIQUIDATION** (мгновенно, в середине раунда) — компактная тост-карточка без затемнения экрана
  (баланс не меняется в этот момент — стейк уже списан при постановке ставки), штамп «LIQUIDATED»
  под углом, магента-осколки.
- Тап/клик в любом месте — мгновенный пропуск, следующая ставка ничем не блокируется. Очередь —
  первые два момента показываются полностью, третий и далее схлопываются в одну сводную карточку
  «+N more results» (раскрывается по тапу, ни одна сумма не теряется).
- Звук выключен по умолчанию, вибрация включена по умолчанию — переключатели рядом в шапке
  (inline-SVG иконки колонки/динамика, `direction.md` §3 — не platform-эмодзи: на Android эмодзи
  рендерился нечитаемым тёмным значком), повторно на самой карточке момента, и ещё раз явными
  строками-переключателями в Wallet/Profile-табе (§8, "Settings" — задача: "settings incl. sound/
  vibration").
  `prefers-reduced-motion` — без тряски/частиц/перелёта, число появляется сразу финальным
  значением, цвет/иконка/текст остаются.

**«While you were away» (добавлено 2026-09-26, новый пункт задачи).** До сих пор момент итога
обнаруживался только пока приложение открыто (`useSettlementWatcher.ts` сравнивает
последовательные наблюдения — если вкладка/приложение было закрыто весь раунд насквозь, момент
никогда не срабатывал, хотя игрок реально выиграл/проиграл). `web/src/fx/useAwayReplay.ts`
закрывает это: при открытии приложения (один раз на вход, не на каждый поллинг) запрашивает
`Api.unseenResults()` — предложение-дополнение к контракту (`contract.ts`, опционально, как
`serverInfo`) — список уже settled раундов игрока, которые ему ещё не показывали. Если метод
отсутствует (сервер ещё не реализовал, или сборка старая) — просто ничего не делает, без ошибки на
экран («fall back gracefully if absent»). Если список не пуст — воспроизводит по одному моменту на
каждый раунд через тот же `resultEventBus`/`ResultQueue` (правило «первые два полностью, дальше
сводная карточка» из §1 выше действует и здесь), с честно восстановленным до/после балансом
(цепочка от текущего реального баланса назад), затем зовёт `Api.acknowledgeResults(roundIds)`,
чтобы те же раунды не показались снова при следующем открытии. Обычный «живой» путь
(`useSettlementWatcher`) тоже зовёт `acknowledgeResults` после каждого показанного момента — иначе
раунд, уже показанный вживую, показался бы второй раз как «unseen» при следующей перезагрузке.

### Раскладка (одна колонка; карточки — адаптивная сетка: 1 колонка на 390 px, 2–3 на десктопе)

Сверху вниз:

1. **Лента категорий** — `role="tablist"` «Market categories»: **"All"** и категории сервера в порядке `CATEGORY_ORDER` (`Crypto · Politics · Sports · Stocks · Indices · Commodities`; неизвестные — в конце), у каждой — число **открытых** рынков (закрытый в число не входит). Прокручивается по горизонтали, липнет под шапкой (`top: var(--header-offset)` — шапка вместе с вырезом телефона), активная вкладка сама встаёт в видимую часть, у края — затухание, пока есть что листать.
2. **Чипы** — **"Hot"**, **"Closing soon"**, **"Favorites"** (переключатели-таблетки, `aria-pressed`, 40 px). Hot и Closing soon — **сортировки**, не фильтры (ничего не прячут): Hot — первым рынок с крупнейшим пулом открытого раунда, тег **HOT** у трёх первых, если пул больше нуля; Closing soon — первым то, что закрывается раньше (окно ставок раунда или конец события у шансов). Строка под чипами называет, что сделано: **"3 markets · biggest pools first"**. Favorites — фильтр по звёздочкам (хранятся в этом браузере).
3. **Поиск** — **"Search markets"**; все слова запроса должны найтись в тикере, названии, подзаголовке (исход), id или названии категории («sports» открывает панель, «ger» находит GER). Крестик **"Clear search"**.
4. **Карточки рынков** (ниже); закрытые рынки всегда в конце.
5. Внизу: отметка про ботов (если сервер сообщает, что боты в игре, Р-46, §2), строка о том, что цены и шансы показаны так, как их публикуют источники, и ссылка **"How it works"**.

Состояние (панель, сортировка, избранное, запрос) живёт в адресе: `/?c=sports&sort=hot&fav=1&q=ger`, запись через `replace` (история не раздувается). Поэтому Back из комнаты возвращает на ту же панель, а ссылкой можно открыть лобби на панели. Панель из устаревшей ссылки (такой категории нет) читается как All.

### Карточка рынка (`MarketCard`)

Вся карточка — одна ссылка в комнату (`/play/:marketId`); звезда, бейдж Herd и кнопки лежат поверх и работают отдельно.

- **Шапка**: значок рынка (картинка источника, при ошибке — буква), тикер, звезда избранного (зона нажатия 44 px), теги **ODDS** / **HOT**, справа — цена и суточное изменение со стрелкой и знаком (**"▲ +1.20% 24h"**; цвет не единственный сигнал). У ODDS — вопрос в две строки, исход и вероятность в процентах.
- **Раскол толпы** — полоска по ставкам **"▲ UP 61% · ● 12 playing · 39% DOWN ▼"** (живой расклад на каждой карточке, Р-62/Р-71). Пустой раунд — честно **"No bets yet"**.
- **Мета**: длина серии и **"Closes in mm:ss"** (спокойный отсчёт без эскалации последних секунд — 18 карточек тикают одновременно; время серверное, `serverOffsetMs`), у ODDS — **"Event ends in 5h 12m"**; бейдж **"Herd +2.40%"** со стрелкой (доходность счёта толпы по этой паре; ведёт в её статистику; пока толпа не торговала — **"Herd — no trades yet"**).
- **Кнопки UP / DOWN** — ссылки в комнату с уже выбранной стороной (`?side=up|down`); у стороны большинства тег `herd`.

### Состояния

- **Loading** — скелеты ленты и карточек. **Error первой загрузки** — общий паттерн §2 с **"Try again"**. **Связь потеряна после удачной загрузки** — карточки остаются, над ними **"Can't reach the server — showing the last prices we got, they may be out of date."**
- **Пусто** — **"No markets are open right now."**; **нет совпадений поиска** — **"No markets match “…”."**; **панель или фильтр без рынков** — **"Nothing here yet."**; у обоих кнопка **"Show all markets"**; **нет избранного** — **"No favorites yet"** / **"Tap the star on a market to keep it here."**
- **Карточка**: живая · ODDS · **stale** (цена приглушена, **"Stale · 3 min ago"**; ставки не блокируются) · **нет цены** (**"—"**, **"Waiting for a price"**, кнопки выключены — раунд без цены рассчитать нельзя) · **закрыт** (**"Closed — open bets refunded. This market takes no more bets."**, без кнопок, цена подписана как последняя) · открыт без серий (**"No rounds are open on this market yet."**). Все — в `/lab/states` (§2).

## 3b. Экран Pair room (`/play/:marketId`) — комната рынка (переписано 2026-10-02, Р-69/Р-70/Р-71)

Статус: **реализовано в `web/`** (`pages/PairRoomPage.tsx`, `components/PriceChart.tsx`, `BetSlip.tsx`). Версия 2026-09-26 («комната BTC, остальные пары — coming soon») заменена: комната есть у каждого рынка каталога, ключ комнаты — рынок.

### Назначение

«Заходишь в конкретную пару и далее уже по этой паре вверх-вниз» (Алекс, Р-59): график, раунды серий, арена, ставка с плечом — для ОДНОЙ пары. Публичный для просмотра, ставка требует кошелька. Адрес: `/play/BTC`, `/play/xyz_NVDA`, `/play/PM900104` (id без учёта регистра, `/play/btc` работает); `?side=up|down` предвыбирает сторону, `?series=daily` — длинную серию. Параметры работают и когда комната уже открыта (карточка полосы «Your bets», §3c, переключает серию без перезагрузки). Переход на другой рынок начинает комнату с нуля.

### Раскладка (одна колонка, desktop и mobile; на десктопе колонка 560 px по центру)

Сверху вниз:

1. **Шапка** — «назад» (на шаг назад по истории приложения; при заходе по прямой ссылке — на панель рынка в лобби), значок, **"BTC/USD"** (у ODDS — тикер без «/USD», тег **ODDS**; у закрытого — тег **CLOSED**), название (и исход для шансов), звезда избранного.
2. **Цена** — крупно, бегущие цифры (`RollingDigits`), суточное изменение со стрелкой и знаком; **"Price is stale"** при устаревшей цене, **"Last price"** у закрытого рынка.
3. Только для ODDS: строка **"You bet on how the odds move during the round — not on who wins. UP: the odds end the round higher than they started; DOWN: lower."**
4. **График** (`PriceChart`, свой SVG без библиотеки): живая цена из `priceSeries`; линия окрашена по движению **с открытия раунда** (выше — зелёная, ниже — красная, ровно — нейтральная) и подписана **"▲ +0.12% vs round open"** (у шансов — в пунктах, **"+0.4 pts"**); чипы диапазона **1M · 5M · 15M** показаны, только если данных хватает на ≥ 90% диапазона, по умолчанию 5M, меньше минуты данных — просто «Live». Линии идущего раунда: цена открытия раунда — она же цена входа всех позиций (Р-8) — одной линией **"OPEN · YOUR ENTRY ▲ x15"**; ваша цена ликвидации — сплошная, у счёта толпы — те же линии бледные пунктирные. Линия, ушедшая за шкалу дальше одной высоты, не растягивает график, а прижимается к краю словами (**"6.6% below"**). Состояния: скелет, **"Waiting for the first prices…"**, **"The price feed isn't answering…"**, **"Reconnecting…"** после удачной загрузки; у закрытого рынка конец линии не пульсирует.
5. Своя позиция (только когда игрок в идущем раунде) — `OwnPositionCard`: живой P&L бегущими цифрами со знаком, полоса оставшегося до ликвидации (доля от дистанции **при входе**, а не сырой процент — x40 стартует в 2,4% от ликвидации и иначе читался бы «критическим» с первой секунды), цены входа и ликвидации; ликвидированная — **"−250 PLAY · liquidated"** / **"You lost your whole stake."** (Р-7).
6. **Серии и отсчёт** — чипы серий по **реальной длине** (`formatDuration`: **"3 MIN"**, **"15 MIN"**, **"1 HOUR"**; Р-19 — на серию всегда один открытый и один идущий раунд), золотая точка у серии, где у игрока открыта ставка; справа **"Closes in…"** (идёт окно ставок) или **"Resolves in…"** (раунд идёт). Строка честности про оракул с источником этой пары (§2).
7. **Арена** (Р-62: «показывать всё вживую», заменяет Р-22) — два больших блока UP/DOWN на всю ширину, ширина каждого — его доля от суммы ставок; тап во время окна ставок выбирает направление (то же направление, что в слипе: `BetSlip` получает `direction`/`onDirectionChange`/`hideDirectionPicker`). Пока идёт раунд — арена выключена и показывает текущий раскол. Под ареной: **"{N} players have voted · a UP / b DOWN"**.

   **Наклейка «Round running»** (правка 2026-09-26, fix item 3, сохранена). Раунд, на который игрок поставил, не исчезает при закрытии окна ставок: по конвейеру Р-19 `RoundsPairDto.betting` в тот же момент переключается на СЛЕДУЮЩИЙ раунд, и арена продолжала бы ярко показывать уже новый раскол без единого подтверждения, что раунд игрока закрылся. В момент такого перехода, если у игрока была ставка на закрывшемся раунде, поверх арены на ~2,6 с появляется затемнённая наклейка (`.room-arena__lock`): иконка замка, **"Round running"**, сторона игрока (**"You picked UP/DOWN"**). Тап по наклейке снимает её немедленно (ничто не блокирует следующую ставку), иначе гаснет сама; под `prefers-reduced-motion` — без анимации появления. Обнаружение считается отдельно для каждой серии.
8. **Ставка** (§11) — пока открыто окно ставок: **"With the herd" / "Against the herd"**, шкала плеча до **потолка пары** (`MarketDto.maxLeverage`, под шкалой **"x2 – max x10"**), сумма (**"Available"**, «−/+», фишки 25 · 50 · 75 · MAX), превью ликвидации, итоговая строка, **"PLACE BET"**. Без входа — тот же слип в режиме превью (§11).
9. **Живая лента ставок** (Р-62) — **"Live bets"**: `RoundBetting.recentBets` (опционально; на сервере без поля блока нет): ник + BOT-бейдж + сторона + плечо + сумма, новые сверху.
10. **Идущий раунд**: **"Crowd account"** (`CrowdPositionCard`) и **"Live round"** — компактная сводка (правка 2026-09-26, fix item 1, сохранена): **"{N} players in this round"**, ссылка **"See all positions →"** на `/round/:id` и до четырёх чипов-«movers» с наибольшим живым P&L **по модулю** (выигрыш и проигрыш поровну; ликвидация — фиксированный `−stake`). Полный список остаётся на `/round/:id` (§4).
11. Ссылки **"View full round →"** и **"How the herd is doing on BTC →"** (в `/stats?m=BTC`, §5), внизу — полка **"More in <Category>"** (`MarketRail`: другие открытые рынки панели).

Момент итога раунда (result-moment.md) — глобальный оверлей, не завязан на этот экран; он называет рынок (§2, §4).

### Состояния

- **Loading** — скелеты шапки, графика, арены. **Error** — общий паттерн §2. **Неизвестный рынок** — **"Unknown market."** + **"Back to Lobby"** (не 404; настоящая 404 — только для маршрута, не совпавшего вовсе).
- **Рынок закрыт** (`status: CLOSED`) — вместо арены и слипа карточка **"This market is closed"**: **"It takes no more bets. Any bet that was still waiting for its round, or in a round that had not ended, was cancelled and refunded in full; rounds that had already ended were settled as usual."**, причина сервера дословно (если есть), кнопки **"Open markets in this panel"** и **"How the herd did here"**.
- **Раунд отменён** — **"This round was cancelled."** и причина сервера дословно. **Нет большинства** (пустой раунд или ничья) — herd-кнопки выключены, строка говорит почему. **Цена stale** — **"Price is stale"**, ставки не блокируются.
- Остальное (not signed in / below min stake / insufficient balance / already bet / betting closed) — как в слипе, §11.

## 3c. Полоса «Your bets» (во всех экранах) — добавлено 2026-10-02 (Р-71)

Статус: **реализовано в `web/`** (`components/PositionsStrip.tsx`, `positionsStripModel.ts`, встроена в `Layout`).

### Назначение

У Polymarket позиции лежат внутри раздела; у Herd все ставки игрока по всем парам видны на любом экране: ставка в BTC не теряется, пока игрок смотрит спорт. Это та же мысль, что «событие видно с любой страницы» (`game-designer.md`): жить с несколькими раундами сразу должно быть легко.

### Раскладка

Секция **"Your bets"** с числом позиций, в потоке страницы над содержимым (в `Layout`, перед `<Outlet/>`) — **не** прижата к экрану, уезжает вместе со страницей и потому ни при каких условиях не закрывает главную кнопку слипа на телефоне. Шапка секции — кнопка (сворачивает полосу до одной строки, выбор помнится): справа сумма живого P&L по идущим позициям (**"+12.40 PLAY live"**) и, если есть, **"N liquidated"**. Ниже — горизонтальный ряд карточек, одна на ставку:

- тикер, сторона стрелкой и цветом (**"▲ UP"**), плечо **"x15"**, время: **"starts 00:41"** (ждёт старта) или **"ends 01:35"** (идёт);
- крупно P&L со знаком (**"+4.96 PLAY"**) и тонкая полоса оставшегося до ликвидации (цвета нагрева, доля дистанции при входе);
- ставка и длина серии; тап — в комнату этого рынка на нужной серии (`/play/ID?series=…`).

### Состояния

- **Нет входа или нет открытых ставок** — полоса не рисуется и **не опрашивает даже список рынков** (дешёвая внешняя часть, `StripBody` — только когда есть что показывать).
- **Ставка ждёт старта** — **"Bet placed — waits for the round to start"**, без выдуманного P&L. **Идёт, цены пока нет** — **"Live — waiting for a price"**.
- **Ликвидирована** — **"−300 PLAY liquidated"** с трещиной и словом, магентовая рамка, до расчёта раунда (`MyPositionDto.liquidated` приходит сразу). Выглядит так же заметно, как плюс (честность: проигрыш виден не меньше выигрыша).
- **Свёрнута** — одна строка: число, живой P&L, число ликвидированных.

## 4. Экран Round (`/round/:roundId`)

**Обновлено 2026-10-02 (Р-69/Р-71; реализовано в `web/`, `pages/RoundPage.tsx`, `components/AnchorLine.tsx`, `fx/ResultCard.tsx`):**

- **Рынок назван везде.** Шапка раунда — **"BTC · 3 MIN"** ссылкой в комнату этого рынка (`/play/BTC`); заголовок итога — **"{тикер} closed UP/DOWN/FLAT — {open} → {close}"**, числа форматируются по рынку (цена, а у шансов — проценты). Длина берётся из окна самого раунда (`endMs − startMs`), а не из слов Hourly/Daily (на стенде серии 3 и 15 MIN). Момент итога (§2) называет рынок второй строкой: **"ETH · stake 250 PLAY · x12 · 1 HOUR round"**; в истории профиля (§7) — **"ETH · 1 HOUR"** в заголовке тайла.
- **"Anchored on Chia"** (Р-40/Р-41) — на разрешённом раунде под строкой честности про оракул: где запись оракула этого раунда на цепи (`RoundSettled.oracleAnchor { seq, state, height }`), по состоянию сервиса цепи (`docs/research/chain_service.md`): **CONFIRMED** — **"Anchored on Chia"**, **"Oracle record #412, confirmed at block 4,738,927 on testnet11."**; **SENT** (`in_flight`) — **"Being anchored on Chia"**; **QUEUED** — **"Waiting to be anchored on Chia"**, «goes out with the next batch», без обещанного срока; **PENDING** (`unknown`) — **"Not anchored yet"**, «hasn't reached the publishing queue»; **CONFLICT** — **"Not anchored — conflict"** (в цепи уже другая запись с этим `seq`: запись удержана и помечена, а не публикуется молча). Под ним — хеш итогов и ссылка **"verify results.json"**. Нет ни якоря, ни хеша (старый сервер, мок) — блока нет вовсе: слово «anchored» не говорится без того, что за ним стоит. Рядом остаётся **"…published by our team's key — not a decentralized oracle."** (§2), теперь с настоящим источником пары.
- **Своя позиция** на идущем раунде — тот же `OwnPositionCard`, что в комнате (§3b): живой P&L, полоса оставшегося до ликвидации, ликвидированная — **"−N PLAY · liquidated"**.
- **Отмена** — у отменённого раунда нет шапки-героя, поэтому `CancellationNotice` подписан контекстом **"GER · 3 MIN"** (иначе не понять, на каком рынке был раунд); причина сервера — дословно, как раньше.

Полная картина одного раунда: пока идут ставки — бет-слип и счётчик участников (Р-22); после
старта — раскрытые позиции всех игроков и позиция счёта толпы; после закрытия — итог; при
отмене — причина.

### Desktop-раскладка

Двухколоночная: слева — цена/таймер/статус-бейдж (карточка `card--hero`, дизайн-редизайн
2026-09-25) и (в фазе BETTING) бет-слип §11 или (после раскрытия) позиции игроков, справа —
карточка позиции счёта толпы (то же, что на публичной Crowd-странице, но только по этому раунду)
и, если раунд уже разрешился, разбор: цена открытия/закрытия, кто выиграл/проиграл, изменение
баланса игрока (если он участвовал). Позиции игроков — «сцена» (`PositionsList`, дизайн-редизайн
2026-09-25: `docs/product/design/direction.md` §4 "Stage/split-camp"; audit.md: раньше это был
«отсортированный список транзакций», не видно было раскола толпы) — две визуально разделённые,
цветом-washed панели UP/DOWN (зелёная/красная), каждая со своим счётчиком и списком игроков как
чипов (аватарка-инициал + ник + BOT-бейдж + плечо + net/live P&L цветом); пустая сторона не
схлопывается — показывает **"No one yet"** на своём цветном фоне.

  таймер **"Closes in {mm:ss}"**, строка **"{N} players have voted"** (только число, Р-22 — это
  headcount, не направления), и, **добавлено 2026-09-26 (Р-62, заменяет Р-22 для агрегата)**, если
  `upStake`/`downStake` присутствуют и хотя бы одна сторона ненулевая — строка **"{pct}% UP ·
  {pct}% DOWN"**: сам раскол ставок теперь виден вживую во время окна ставок, не только число
  проголосовавших (полная арена с этим же расколом — на Pair room, §3b; здесь — компактная
  текстовая версия того же факта). Далее бет-слип §11 или заглушка «Not signed in» / «already bet»
  ниже.
- **Round running** (`phase: "RUNNING"`) — бейдж **"LIVE"** (красный, пульсирующий), таймер
  **"Resolves in {mm:ss}"**, цена открытия, список раскрытых позиций (направление, плечо, ник),
  карточка толпы с направлением/плечом/маржой/ценой входа/ценой ликвидации. Строка честности про
  оракул (§2). **Раскрытие при старте раунда** (дополнено 2026-09-25, `live-round.md` §3) — герой-
  карточка и список позиций один раз проигрывают короткий flip/каскад ровно в момент перехода
  BETTING→RUNNING (не повторяется на каждый последующий тик поллинга); под `prefers-reduced-motion`
  — обычный fade без 3D. **Живая шкала до ликвидации** (`live-round.md` §2) — герой-карточка своей
  позиции получает пульсацию (по тому же рампу зон Watch/Close/Critical, что и `LiquidationBar`) по
  мере приближения текущей цены к цене ликвидации. **Живой P&L во время RUNNING** (usability-фикс 2026-09-25, отчёт Алекса: до фикса
  своя позиция во время раунда показывала только текст «Your position is live.» — без единой
  цифры игрок не мог понять, выигрывает он или нет) — своя позиция и позиция толпы каждый тик
  поллинга (§7 вопрос 7 — тот же интервал, что у самого раунда) пересчитывают нереализованный P&L
  от текущей референсной цены (`btcReferencePrice()`, уже опрашивается бет-слипом) и цены
  входа/размера позиции: заголовок **"{sign}{amount} PLAY"** (своя позиция) /
  **"{sign}{amount}"** в USD (позиция толпы, торгует paper-USD, не PLAY — Р-17), подписано мелким
  приглушённым текстом **"unrealized"**, ниже — **"{pct}% to liquidation"** (та же формула, что у
  превью до ставки, §11, но от текущей цены, а не от цены входа — расстояние до ликвидации
  сокращается по мере приближения цены).
- **Liquidated** (своя позиция, в списке позиций или в персональной плашке сверху, если это
  позиция вошедшего игрока) — заголовок net-результата (см. ниже) красным с суффиксом
  **" · liquidated"**, например **"−100.00 PLAY · liquidated"**, под ним мелким текстом
  **"You lost your whole stake."** (Р-7). Для позиции толпы — отдельная плашка
  **"Crowd account liquidated this round."** над её net-результатом в USD.
- **Settled** (`phase: "SETTLED"`) — бейдж **"SETTLED"**, заголовок
  **"BTC closed {UP/DOWN/FLAT} — {open} → {close}"** (usability-фикс 2026-09-25: `FLAT`, когда
  `close === open` — без этого варианта плоское закрытие показывало бы «UP», хотя Р-27 явно
  трактует его как «ни туда ни сюда» — `directionCorrect` для такого раунда `null` и он исключён
  из знаменателя рейтинга Prophets).

  **Итог по NET-результату, не по знаку payout** (usability-фикс 2026-09-25, отчёт Алекса: «я не
  вижу, чтобы выигрывали, все проигрывают ставки» — все экраны судили won/lost по `payout > 0`,
  поэтому проигрышная позиция, вернувшая часть маржи (например, 80.15 PLAY со ставки 100), тоже
  показывалась как «You won 80 PLAY»). Везде, где раньше был won/lost/liquidated-текст на основе
  payout — теперь заголовок net-суммы **"{sign}{net} PLAY"** (`net = payout - stake`), цветом по
  знаку (зелёный `net > 0`, красный `net < 0`, приглушённый `net = 0`) — сам лейбл «won»/«lost»
  выводится из этого же знака, не из payout. Для своей позиции — под заголовком мелким
  приглушённым текстом строка **"stake {stake} → paid {payout}"** (payout как было, вторым планом,
  а не единственным числом). Для каждой публичной позиции в списке (`PositionsList`) и в истории
  профиля (§7) — та же net-сумма, без вторичной строки (компактный список). Карточка толпы —
  такая же net-сумма в USD над капиталом до/после.
- **Cancelled with reason** (`phase: "CANCELLED"`) — бейдж **"CANCELLED"** (серый), карточка:
  **"This round was cancelled."**, ниже точная причина из `CancellationDto.reason` **как есть,
  без перевода/перефразирования** (публичная прозрачность, Р-32), строка
  **"All {N} bets were refunded, including any that would have been liquidated."** (Р-23).
- **Not signed in** (во время BETTING) — вместо бет-слипа превью (`BetSlipPreview`, §11 "Not
  signed in — preview mode"); на Round дополнительно показывает подсказку **"You can still watch
  this round without one."** (`noPlayerHint`).
- **Insufficient balance** (при попытке поставить) — под полем стейка:
  **"Not enough PLAY — you have {balance} PLAY, this bet needs {stake} PLAY."**, кнопка
  подтверждения задизейблена.
- **Below min stake** — под полем стейка: **"Minimum stake is 100 PLAY."**, кнопка задизейблена.
- **Already bet this round → edit/cancel** — бет-слип заменяется карточкой текущей ставки:
  **"Your bet: {UP/DOWN} · x{leverage} · {stake} PLAY"**, две кнопки: **"EDIT BET"** (открывает
  тот же бет-слип, предзаполненный) и **"CANCEL BET"** (после подтверждающего диалога
  **"Cancel your bet and get {stake} PLAY back?"** / **"KEEP BET"** / **"CANCEL BET"**).

### Копирайт (сводка новых строк, не повторяющихся выше)

локальном тестовом стенде вход вовсе не требует Sage, см. §10, шаг 1).

### Раскладка (одна и та же по составу на desktop/mobile)

Под заголовком **"Wallet"** — факт **"PLAY — test tokens on Herd's test network. Nothing here is
real money."** обычным текстом (не баннером, §2), и (только в тестовом режиме, `serverInfo()`)
строка режима replay/ботов. Затем баланс крупно (**"{balance} PLAY"**), под ним — история движений
баланса (`LedgerEntryDto[]`, читаемый маппинг типа в текст — см. ниже), с пагинацией. Затем три
информационных блока: **"Withdraw to wallet"**, **"Deposit from wallet"** и **"Settings"** — на
desktop рядом с историей (двухколоночно), на mobile ниже неё в одну колонку.

**Правка 2026-09-26 (Р-53 — реализация после блокера независимой критики):** оба блока снова
живые формы/виджеты, но не те же самые, что были до блокера — старый `DepositForm` («сумма,
которую вы отправили» + опциональная ссылка на транзакцию → «I sent it») мгновенно и безусловно
зачислял любую самозаявленную сумму без проверки в сети (живой репродукции критика хватило десяти
секунд, чтобы напечатать 5 000 000 PLAY) и **не возвращается ни в каком виде** — весь класс
«игрок сам говорит, сколько он отправил» закрыт навсегда (`server/`: `requestDeposit` теперь
безусловно отклоняет любой вызов). Новая механика вместо него:

- **"Deposit from wallet"** больше не форма ввода суммы — это адрес. Сервер (task's FIXED
  INTERFACE, chainsvc `POST /v1/play/deposit-address`) выдаёт игроку персональный, стабильный на
  весь сезон/аккаунт адрес PLAY CAT; экран показывает его текстом (моно, с переносом) + QR-код +
  кнопку **"Copy address"**. Копирайт: **"Send PLAY from Sage to this address — credited after
  confirmation on testnet11 (~1–5 min)."** Игрок сам отправляет PLAY со своего кошелька (Sage) —
  зачисление происходит автоматически на сервере, как только депозит подтверждён на цепи; никакой
  кнопки «I sent it» или поля суммы нет и не может быть. Пока идёт ожидание, под адресом — тихая
  строка живого статуса: **"● Watching for deposits — this page checks automatically."**
  (`live-dot`, пульсирует, `prefers-reduced-motion` уважается) — сам факт зачисления виден не
  отдельным баннером, а тем, что баланс сверху докручивается (`RollingDigits`) и вспыхивает, плюс
  новая строка `DEPOSIT` появляется в истории — экран уже полагается на периодический опрос
  (`myAccount`/`myLedger`), больше ничего изобретать не пришлось.
- **"Withdraw to wallet"** — снова форма: поле **"Amount (PLAY)"**, ниже — **не редактируемая**
  строка **"Destination — your registered address:"** с сокращённым адресом игрока (Р-57: адрес
  назначения — всегда тот же адрес, которым игрок зарегистрировался, никогда не свободное поле —
  скомпрометированная сессия не может увести вывод на чужой адрес), кнопка **"Withdraw"**.
  Валидация (клиентская, зеркалит сервер): положительная сумма, не больше 3 знаков после запятой,
  не больше баланса, не меньше минимума вывода (`MIN_WITHDRAWAL_PLAY`, предложение — 100 PLAY,
  тот же порядок, что минимальная ставка, но отдельная константа: комиссия чейнсвика на маленьком
  выводе съела бы непропорционально много). После отправки — список «Recent» под формой с одной
  строкой на запрос: сумма + бейдж статуса, тот же визуальный паттерн, что `RoundStatusBadge`
  (жёлтый пульс → красный пульс → зелёный/серый): **QUEUED** («Waiting for the next treasury
  batch.») → **IN FLIGHT** («Submitted to testnet11 — waiting for confirmation.») →
  **CONFIRMED** (id монеты + высота блока, обычным моно-текстом, НЕ ссылкой — публичного
  эксплорера testnet11, который бы стабильно отвечал, на 2026-09-25 не существует,
  `docs/research/week1_testnet_results.md`) или **FAILED** (причина отказа текстом; сумма уже
  автоматически возвращена на баланс — `WITHDRAWAL_REFUND` в истории ниже).

Баланс — не статичный текст: крутится через `RollingDigits` (тот же компонент, что момент итога и
шапка) и на 1 цикл вспыхивает рамкой `--win-neon`/`--loss-neon` по знаку изменения при обновлении
(`direction.md` §0, `live-round.md` §5 — тот же паттерн, что стат-плитки `Crowd`). Каждая строка
истории — с иконкой по типу слева от текста (`direction.md` §3): `STARTER_PACK` — подарок,
`STAKE_DEBIT` — фишка, `STAKE_REFUND`/`WITHDRAWAL_REFUND` — стрелка-возврат, `DEPOSIT` — стрелка
вниз, `WITHDRAWAL` — стрелка вверх, `SETTLEMENT` — та же иконка, что момент итога, по знаку
`delta` (кубок/минус-диск/равно).

**Блок «Using Sage? Four things to know» (2026-10-02, `components/SageHints.tsx`; реализовано в `web/`).** Сразу под `DepositCard` — карточка с четырьмя пунктами, каждый из которых реальный игрок споткнулся при первом входе через настоящий Sage (`docs/research/sage_real_e2e.md`, «Трение»): (1) **Network** — Sage стартует на mainnet, переключить на **testnet11** (Settings → Network → Default network); (2) **"Unknown CAT"** — PLAY показывается в Sage под этим именем (нет в списке токенов), поэтому полный **asset id** `0x4b88ce97…080b70` моноширинным текстом с кнопкой **"Copy asset id"** (`docs/research/week1_testnet_results.md:60`; сервис цепи читает его из своего состояния, `chain/c2-svc/src/play/deposit.rs:169`; в вебе — константа `playAsset.ts`, при другой сети — `VITE_PLAY_ASSET_ID`; в `ServerInfoDto` поля нет — нужно от сервера); (3) **Fee** — при отправке PLAY на адрес депозита выставить сетевую комиссию около **0.0005 TXCH** (500 000 000 mojo; на загруженном testnet11 перевод с нулевой комиссией не проходит); (4) **Signing in again** — каждый вход через Sage это новое подключение WalletConnect: скопировать ссылку в Herd и вставить в Sage → Settings → WalletConnect, после перезагрузки страницы оно не помнится. В окне входа на шаге с QR показаны две краткие подсказки из этого же набора (сеть и «новое подключение»; на том же телефоне сканировать нечем — только вставить ссылку).

## 10. Первый вход (first-time flow)

Шаги, экран за экраном, с точным копирайтом. Источники: Р-2, Р-4, Р-12, Р-15, Р-55, Р-57,
`docs/research/week1_wallet_auth.md` §4 и её раздел «Реализация».

**Шаг 0 — старт.** Новичок на Home видит продукт без входа (просмотр публичен), жмёт
**"CONNECT WALLET"** в header или в любой карточке-приглашении.

**Шаг 1 — подключение кошелька.** Модальное окно: заголовок **"Connect your wallet"**, теперь с
двумя путями (Р-55 — реализован в эту задачу; раньше был только тестовый кошелёк).

**Порядок путей — правка 2026-10-02 (`docs/HANDOFF.md` §6 п. 10, реализовано в `ConnectWalletModal.tsx`):
тестовый кошелёк идёт ПЕРВЫМ и основной кнопкой, Sage — вторым, спокойной вторичной кнопкой,
между ними разделитель «or».** Причина: на этом стенде тестовый кошелёк — единственный путь, который
работает у любого посетителя; кнопка Sage первой была тупиком для того, у кого Sage нет (а пока нет
`projectId`, она и вовсе выключена). Описание ниже сохранено по составу, порядок читать так:

- *(теперь вторым, после разделителя «or»)* Кнопка **"Connect with Sage"** (реальный вход через WalletConnect v2). Пока у Алекса
  нет зарегистрированного Reown `projectId` (регистрация не в этой сессии — правило проекта об
  исходящих действиях), кнопка задизейблена, под ней строка **"Coming soon — needs WalletConnect
  project id."** Как только `projectId` появится (сборочная переменная
  `VITE_WALLETCONNECT_PROJECT_ID` ИЛИ — без пересборки образа — `ServerInfoDto
  .walletConnectProjectId` с сервера), кнопка включается сама, без правки этого экрана. По клику —
  окно переходит в **"Connect with Sage"** (шаг 1a ниже); тестовый кошелёк остаётся доступен
  рядом — оба пути не исключают друг друга.
- *(теперь первой)* Плашка **"TEST WALLET"** (Р-45, task item 2 — «shows 'Test wallet' clearly»), текст
  **"Fastest way in: this stand signs you in with a real Chia key generated right in your
  browser — not Sage. It doesn't move any funds, and each browser/profile is a separate
  player."** (закрывает часть вопроса 1 из §12 — что происходит и что это не транзакция; честно
  называет, что это НЕ Sage — `web/src/wallet/testWallet.ts`, реальная BLS-подпись, не имитация),
  кнопка **"Continue with test wallet"**. По клику — запрос challenge (`authChallenge`), затем
  реальная подпись в браузере (`chia-wallet-sdk-wasm`, та же схема, что и у Sage,
  `docs/research/week1_wallet_auth.md` §2). Состояние ожидания: **"Signing in with your test
  wallet…"** со спиннером (подпись сама почти мгновенна — WASM, без сети — короткая пауза здесь
  только чтобы состояние было заметно).

**Шаг 1a — Sage/WalletConnect (Р-55, только когда `projectId` есть).** Заголовок **"Connect with
Sage"**. Пока идёт пейринг — спиннер, **"Opening a connection to Sage…"**. Как только
WalletConnect отдал `uri` — QR-код (desktop: сканировать телефоном) + кнопка **"Copy connection
link"** (то же самое соединение, для случая «Sage на этом же устройстве» — вставить ссылку в само
приложение Sage), две краткие подсказки про сеть testnet11 и про то, что каждый вход — новое подключение
(2026-10-02, `SageSignInTips`; полный набор — на экране кошелька, §8), и текст **"Open Sage on your phone or desktop, scan this code, then approve the
connection and the sign-in message it shows you."** После подтверждения пейринга — состояние
**"Waiting for the sign-in message to be approved in Sage…"** (второе, отдельное подтверждение в
Sage — реальная подпись challenge-сообщения, `chia_signMessageByAddress`,
`docs/research/week1_wallet_auth.md` §1.1/§2). Идентичность игрока (Р-57): при первом входе адрес
берётся из ответа Sage (`chia_getAddress`); при каждом следующем входе с этого же браузера
используется **тот же** адрес, что и в первый раз (сохранён локально как подсказка, не как
доказательство — сам факт входа всё равно каждый раз проверяется настоящей подписью), даже если
у Sage с тех пор сменился активный адрес получения. Ошибка на любом шаге (отклонена в Sage,
реле недоступно, …) — экран **"Couldn't connect"** с текстом причины и кнопками **"Try again"**/
**"Cancel"**, не тихое зависание.

**Шаг 2 — выбор ника** (только если `AuthSessionDto.isNewPlayer === true`, Р-15). Экран:
заголовок **"Pick a nickname"**, текст **"Shown next to your wallet address — {shortAddress}."**,
поле ввода, мелкая строка (§2) **"Ratings are for fun — we don't detect multiple accounts."**,
кнопка **"CONTINUE"** (задизейблена, пока поле пусто).

**Шаг 3 — стартовый пакет.** Экран-подтверждение: крупно **"You've got 10,000 PLAY"**, ниже
**"Toy money for this demo — place your first bet or explore the crowd account."**, две кнопки:
**"PLACE A BET"** (ведёт на Home/Round с открытым бет-слипом) и **"EXPLORE"** (закрывает модалку,
остаётся на текущей странице). Начисление уже произошло на бэкенде при первой активности
(`ensureSeasonPack`, движок) — этот экран только показывает свершившийся факт, не отдельный шаг
запроса.

**Шаг 4 — первая ставка.** Открывается бет-слип §11, предзаполненный ничем (чистая форма);
дальше — обычный путь ставки.

## 11. Bet slip — детальная спецификация

**Обновлено 2026-10-02 (Р-69/Р-71; реализовано в `web/`, `components/BetSlip.tsx`, `betSlipModel.ts`, `LeverageDial.tsx`, `heat.ts`).** Что изменилось против описания ниже; где пункт ниже противоречит этому абзацу, верен этот абзац:

- **Потолок плеча — `maxLeverage` рынка** (а не константа 40): шкала идёт от `LEVERAGE_MIN` до потолка пары, значение выбора ограничено им (`Math.min(выбор, maxLeverage)`), под шкалой всегда **"x2 – max x10"**. Нагрев `--heat-1..5` считается **долями потолка** этой пары (20 / 37,5 / 60 / 82,5%): на x40 это в точности прежние границы x8/15/24/33 (проверено тестом по всем x2…x40), на потолке x10 «все деньги» — Flame. Превью ликвидации считает сервер (`previewLiquidation({ marketId, … })`), клиент его не пересчитывает.
- **Сумма**: большое поле по центру с подписью PLAY, кнопки **"−" / "+"** по обе стороны (шаг — минимальная ставка, 100 PLAY; не ниже нуля и не выше баланса, а сумма ниже минимума выключает «PLACE BET» и говорит почему — «Валидация» ниже), под полем **"Available: 9,420 PLAY"** и фишки **"25%" · "50%" · "75%" · "MAX"** от доступного баланса (`aria-pressed` на выбранной, у MAX читаемое имя «MAX — your whole balance»; проценты округляются вниз до целых PLAY, чтобы сумма была аккуратной и никогда не превышала баланс; MAX — весь баланс до тысячной PLAY, чтобы ничего не оставалось). **Заменяет** аддитивные **"+100"/"+500"/"+1000"/"MAX"** (прежний пункт «Stake» ниже): так делает лист ордера мобильного Polymarket, и процент от баланса понятнее новичку, чем «+500». Зоны нажатия ≥ 44 px.
- **"With the herd" / "Against the herd"** (Р-71, наша фишка; `HerdPicker`) — над шкалой плеча две равные по весу кнопки: одно касание ставит сторону большинства (по PLAY, которое уже на сторонах сейчас) или противоположную. Каждая называет сторону (**"▲ UP"** / **"▼ DOWN"**), выбранная — `aria-pressed`. Это ускорители, не совет: ни слова о том, что толпа права или неправа; подсказка не прячет, что в толпе боты: **"The herd is the side with more PLAY on it right now — players and test bots together."** Нет большинства (пустой раунд или ровно поровну) — обе выключены, строка **"No herd yet — the crowd is split evenly, or nobody has bet."** Блок работает и в режиме превью без входа.
- **Итоговая строка перед кнопкой**: **"250 PLAY · ▲ UP · x12 on ETH · 1 HOUR round"** (у шансов — **"x4 on GER odds · 15 MIN round"**): какая пара, какая сторона, сколько, насколько горячо — ещё раз прочитать перед нажатием.
- **Значения по умолчанию**: сторона UP, плечо **x10** (не больше потолка пары), сумма **100** (минимум). Кнопки UP/DOWN карточки рынка ведут сюда с уже выбранной стороной (`?side=`) — это предвыбор, а не ставка: «PLACE BET» слип не нажимает никогда.
- **Исправление ошибки React** (была и до этого шага): слип вызывал `setState` родителя прямо во время рендера («Cannot update a component while rendering a different one»); теперь сторону существующей ставки он сообщает родителю из эффекта, а новый раунд не сбрасывает уже выбранную сторону.

Используется на Pair room (встроенно, направление выбирается ареной — см. ниже) и на Round
(полноразмерно, со своими кнопками UP/DOWN) — один и тот же компонент, на desktop и на mobile
(Р-48). **Добавлено 2026-09-26**: `BetSlip.tsx` получил три новых опциональных пропса —
`direction`/`onDirectionChange`/`hideDirectionPicker` — так, чтобы внешний контрол (арена Pair
room, §3b) мог управлять направлением вместо собственных кнопок слипа; без них компонент ведёт
себя ровно как раньше (Round этими пропсами не пользуется). На 375px вся форма — одна колонка на
всю ширину контейнера, каждый интерактивный элемент (UP/DOWN, слайдер плеча, поле стейка, быстрые
кнопки, PLACE BET) — full-width или как минимум touch-target-размера, без горизонтальных пар,
требующих второй руки
или точного попадания — «одной рукой» в буквальном смысле task item 3.

### Поля и порядок (сверху вниз)

1. **Direction** — две крупные кнопки на всю ширину, **"UP"** (зелёная) / **"DOWN"** (красная)
   (Р-33). Ровно одна выбрана в любой момент.
2. **Leverage** — «силовой диск» (`LeverageDial`, дизайн-редизайн 2026-09-25:
   `docs/product/design/live-round.md` §1): визуально стилизованный трек с цветом по рампу
   `--heat-1..5` (зелёный → жёлто-зелёный → золото → оранжевый → красный к x34-40, с лёгкой
   пульсацией трека в зоне x34-40) и крупная цифра **"x{value}"** над треком. Под капотом
   по-прежнему настоящий `<input type="range">`, диапазон `LEVERAGE_MIN..maxLeverage` рынка (для BTC 2..40,
   `contract.ts`; с 2026-10-02 потолок у каждой пары свой — абзац в начале §11), целочисленный шаг 1 — клавиатурная/screen-reader доступность не изменилась,
   изменился только визуальный слой. Дополнено 2026-09-25 (`live-round.md` §1): ambient-искры у
   ползунка в зонах Hot/Danger/Flame и лёгкая вибрация на шаге (частота растёт с зоной, throttle
   ≥80мс во Flame) — отключаются вместе с `prefers-reduced-motion`/тумблером вибрации
   соответственно.
3. **Stake** *(фишки «+100/+500/+1000» ниже с 2026-10-02 заменены на 25 · 50 · 75 · MAX и «−/+», см. абзац в начале §11)* — крупная tabular-nums цифра **"{stake} PLAY"** (`formatPlayAmount`, единый формат
   сумм PLAY во всём приложении — см. исправление 2026-09-26 ниже) над полем точного ввода (поле
   визуально вторичнее цифры и чипов), под полем — фишки-чипы **"+100"**,
   **"+500"**, **"+1000"** (аддитивные — добавляют к уже введённой сумме, с потолком в текущий
   баланс) и **"MAX"** (весь доступный баланс), доступны только вошедшим игрокам. Дизайн-редизайн
   2026-09-25 (`docs/product/design/direction.md` §4 "Chips, not bare inputs") — раньше это были
   **"MIN"**/**"25%"**/**"50%"**/**"MAX"** от текущего баланса; теперь MIN не нужен отдельной
   кнопкой (поле уже стартует со 100 PLAY по умолчанию).

   **Исправление 2026-09-26 (независимая критика — "PLAY amount formatting"):** поле стейка
   раньше было нативным `<input type="number">` со значением, привязанным прямо к
   контрактной строке точности (`MIN_STAKE_PLAY = "100.000"`). На системах с запятой как
   десятичным разделителем браузер отображал это же значение как **"100,000"** — на вид
   тысяча сто, а не сто (интерфейс при этом фиксированно на английском, Р-24). Поле теперь —
   обычный `<input type="text" inputMode="decimal">` с собственным парсингом/санитайзингом
   (только цифры и не больше одной точки), значение по умолчанию — чистое **"100"**, никогда
   контрактная строка целиком.
4. **Liquidation preview** — карточка, обновляется при каждом изменении direction/leverage/stake
   (дебаунс ~150мс, без отдельной кнопки «посчитать» — закрывает вопрос 3 в §12). Дизайн-редизайн
   2026-09-25 (`LiquidationBar`, `docs/product/design/live-round.md` §2): горизонтальная шкала
   вместо двух строк голого текста — слева **"Entry ~${entryPriceUsed}"**, справа
   **"Liquidation price: ${liquidationPrice}"**, заливка = сколько ещё есть «до края», цвет по
   тому же рампу `--heat-1..5`; под шкалой — **"{percentToLiquidation}% move to liquidation"**.
   - мелким текстом под карточкой: **"Estimated from the current price — your real entry price is set when the round starts."**
     (честность про разницу preview/реальной цены входа, см. `MarketReferenceDto` в контракте).
   - заголовок карточки **"Liquidation preview"** со ссылкой **"What's this?"** рядом (usability-фикс
     2026-09-25: leverage/liquidation — незнакомые термины для новичка с бэкграундом
     Manifold/Twitch Predictions, `ux_walkthrough.md` вопрос 4) → `/how-it-works#liquidation`,
     открывается в новой вкладке, чтобы не терять заполненную форму ставки; без отдельного шага
     подтверждения.
5. **Submit** — кнопка **"PLACE BET"** (или **"UPDATE BET"** в режиме редактирования, §4).

### Валидация (клиентская — зеркалит `LedgerBook`/`Leverage` на сервере, контракт §"Engine constants")

- `stake < MIN_STAKE_PLAY` (100 PLAY) → кнопка задизейблена, текст **"Minimum stake is 100 PLAY."**
- `stake > текущий баланс` → кнопка задизейблена, текст
  **"Not enough PLAY — you have {balance} PLAY, this bet needs {stake} PLAY."**
- `leverage` вне 2..40 — недостижимо через слайдер (границы слайдера сами это гарантируют).
- Оба нарушения проверяются заново сервером при отправке (`STAKE_BELOW_MINIMUM`,
  `INSUFFICIENT_BALANCE` из `ApiErrorCode`) — клиентская проверка не единственная линия защиты,
  только для мгновенной обратной связи.

### Режим редактирования («already bet this round»)

Форма предзаполняется текущей ставкой (`RoundBetting.myBet`), кнопка — **"UPDATE BET"**, рядом —
вторичная кнопка **"CANCEL BET"** (см. диалог подтверждения в §4). Отправка `placeBet` с тем же
`roundId` заменяет старую ставку (Р-13, `GameEngine.placeBet`) — отдельного «шага подтверждения
замены» не показываем, серверная семантика уже безопасна (сначала возврат старой, потом резерв
новой).

### Закрытие окна ставок во время заполнения формы

Если `phase` раунда переключился с `BETTING` на `RUNNING`, пока форма открыта (таймер дошёл до
нуля) — форма блокируется немедленно (без ожидания ответа сервера на возможный поздний submit),
показывается: **"Betting just closed for this round."**, кнопка **"View next round"** ведёт на
следующий открытый раунд той же серии.

### Not signed in — preview mode (добавлено 2026-09-26, независимая критика — "Game feel / onboarding")

Раньше бет-слип без входа целиком заменялся карточкой-призывом — новичок не мог увидеть, как
вообще выглядит ставка, до создания кошелька. Теперь `BetSlipPreview` — тот же по составу слип
(direction/leverage/stake/liquidation preview), с двумя отличиями:

- **Доступная подпись поля стейка** — **"Preview stake (PLAY)"**, а не **"Stake (PLAY)"** (иначе
  при недолгом сосуществовании превью и настоящего слипа, пока сессия догружается, у двух полей
  совпадало бы имя для скринридера/автотеста).
- **Кнопка отправки** — не **"PLACE BET"**, а **"CONNECT WALLET"**, над ней —
  **"Connect your wallet to actually place this bet."** Клик открывает тот же флоу входа
  (§10 шаг 1), ничего не отправляется на сервер.

Live-превью цены ликвидации работает без входа как есть: `previewLiquidation` на сервере никогда
не требовал сессии (только `placeBet`/`cancelBet` её требуют) — контракт не менялся. Фишки
**"25%" · "50%" · "75%" · "MAX"** и строка **"Available"** не показываются (в превью нет баланса, к
которому их привязывать) — игрок печатает сумму в поле или жмёт «−/+»; **"With the herd" / "Against the
herd"** в превью работают (раскол толпы виден и без входа).

## 12. Ответы на UX-вопросы (`docs/product/ux_walkthrough.md`)

Нумерация — как в исходном файле.

1. **Онбординг без кошелька.** Отвечено (§10): шаг встроен в сам продукт (модалка при клике
   «Connect wallet» с объяснением, что происходит), не только внешний README.
2. **Первые PLAY** — решено Р-2/Р-4/Р-12, экран подтверждения — §10 шаг 3.
3. **Когда показывается цена ликвидации.** Отвечено (§11): статический калькулятор, мгновенный
   пересчёт при каждом изменении полей, без промежуточного шага/черновика Offer.
4. **Экранное представление голоса** — отвечено §4 (счётчик участников в BETTING, раскрытые
   позиции в RUNNING/SETTLED).
5. **Экранное представление позиции толпы** — отвечено §4/§5 (карточка толпы на Round и на
   Crowd).
6. **Текст/индикатор резолва + хранение истории.** Отвечено: индикатор — статус-бейдж **"SETTLED"**
   + разбор итога на Round (§4); хранение истории — `ProfileRoundEntryDto[]`, экран Profile (§7).
7. **Задержка публичной страницы счёта толпы относительно оракула.** Предложение (не решение
   механики игры, а архитектурный выбор для недели реализации): поллинг, не WebSocket — проще
   для MVP без выделенной инфраструктуры; страница показывает **"Updated {HH:MM:SS} UTC"** рядом
   с ценой/капиталом, чтобы разрыв был явным, а не молчаливым. Финальный интервал поллинга — не
   зафиксирован, решить в неделю реализации Round-экрана.
8. **Ошибки транзакций понятным языком.** Отвечено: `ApiErrorCode` → человекочитаемый маппинг
   (§2, §4, §8), сырой текст ошибки Sage/сервера никогда не показывается.
9. **Где написано про управляемый оракул.** Отвечено (§2, §4, §5, §9) — на каждом экране, где
   от него зависит исход, не только в FAQ.
10. **Виден ли новичок в рейтинге до порога N.** Отвечено (§6): не виден в списке, но видит
    **"Play {K} more rounds…"**. Само число N зафиксировано Р-28 = 10.
11. **Баланс PLAY в реальном времени.** Отвечено: header показывает баланс постоянно (вошедшим
    игрокам), Wallet — полную историю движений (§8); отдельный block explorer не нужен для этого.
12. **Доступность без десктопа.** Изначально решено Р-31 (публичные страницы — просмотр,
    ставки — нет), **заменено Р-48**: всё, включая ставки и Wallet, работает с телефона —
    Р-31's предпосылка «Sage = только desktop» оказалась неверной.
13. **Два раунда одного типа одновременно.** Отвечено (§3, §4): раздельные статус-бейджи
    **"OPEN FOR BETS"** vs **"LIVE"**, на Home бет-слип явно привязан к карточке открытого (не
    идущего) раунда самим расположением (бет-слип рядом со статусом именно открытого раунда, не
    общий на оба).
14. **Экран вывода/возврата PLAY.** Было отвечено предложением — ручное «я отправил, вот
    подтверждение». **Обновлено 2026-09-26** (независимая критика — этот self-report
    зачислял любую сумму без проверки в сети, живой блокер до закрытой альфы): пока
    `OnChainWalletPort` не реализован по-настоящему, экран (§8, Wallet) вместо формы показывает
    честное «временно выключено» — см. §8 Состояния. Форма/статусные тексты, описанные выше,
    остаются планом на момент, когда верификация в сети появится, не текущим поведением.
15. **Поиск контрагента для Offer-обмена.** Отвечено предложением: **вне продукта в MVP** —
    никакой встроенной доски объявлений; продукт из этого файла не порождает интерфейс для
    Offer-обмена между игроками вовсе (не входит ни в один экран §3–9). Обоснование: Р-6
    фиксирует сам механизм (Offer), не обязанность продукта его опосредовать; экономия объёма
    MVP. Решить окончательно с Алексом до недели, где Offer-обмен берётся в работу.
16. **Раскрытие «мультиаккаунты не отслеживаются».** Отвечено (§2, §6, §10 шаг 2) — на экране
    выбора ника, на Ratings, не только в FAQ.
