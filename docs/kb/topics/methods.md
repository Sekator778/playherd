# Опубликованные методы, выбранные по Р-99

Обновлено: 2026-10-21 (раздел «Хранение журнала»). Что это: перечень методов из литературы и отраслевой практики, которые проект выбрал вместо собственных моделей (Р-99: «сначала поиск опубликованного → выбор того, что подходит → применение»), где каждый используется и насколько глубоко источник прочитан. Три группы: экономика и риск казны, стенд замеров, архитектура.

Метки уровня прочтения сохранены как в исходных файлах: [прочитано] — текст получен и прочитан (PDF разобран); [выжимка] — пересказ `WebFetch`, дословность не проверена; [аннотация] — только аннотация или карточка статьи; [сниппет] — фрагмент поиска; [не читал] — книга или платная статья; UNVERIFIED — не проверено. Сокращения: EL = `docs/research/economy_literature_2026-10-17.md`, EM = `docs/research/economy_1m_players_2y_2026-10-17.md`, TS = `docs/research/treasury_solvency.md`, LB = `docs/research/load_bench_design_2026-10-17.md`, LR = `docs/research/lmax_roadmap.md`, AI = `docs/research/architecture_review_independent_2026-10-16.md`. Дата чтения источников в EL, EM, LB — 2026-10-17, LR — 2026-10-16. Скрипты расчётов — `tools/economy/million/` (README там же).

## Коротко для Herd
- Р-99 (2026-10-17): всё, что проект делает (экономика, риск казны, модели, архитектура, методика замеров), уже описано исследователями; сначала поиск опубликованного, свой метод — только там, где опубликованного нет, и с пометкой.
- Экономика: по каждой из 8 задач выбран один метод (EL §0.1); для варианта (e) «казна до λ + пул сверху» точного опубликованного аналога не найдено — это собственная конструкция (EL §0.2).
- Не прочитаны (платные): Asmussen–Albrecher «Ruin Probabilities», McNeil–Frey–Embrechts «Quantitative Risk Management», Lehdonvirta–Castronova «Virtual Economies» (EL, шапка). Их формулы в проект не переписаны.
- Стенд замеров: построены pgbench-потолок Postgres (шаг 1), JFR-инструментирование сервера (шаг 2), засев и сборщик журнала (шаг 3), генераторы Gatling и wrk2 с отчётом на HdrHistogram (шаг 4, `tools/bench/gen/`); JMH и подгонка USL — только в проекте.
- Архитектура: LMAX/Disruptor — выбранное направление (Р-95, Р-96), но шаги 3+ не сделаны; TigerBeetle в замерах не берётся, в архитектуре — «сейчас не нужен» (AI §2.5).

### Конвейер писателя (LMAX: логика не ждёт диск; прочитано 2026-10-21)
| Что | Факт | Источник |
|---|---|---|
| Что говорит Fowler | «the central idea of Business Logic Processor is that it avoids doing any IO»; журналирование, репликация и разбор входа делаются до BLP, «they can done in any order» (параллельно); «This batch read of the data from the disruptor makes it easier for lagging consumers to catch up quickly»; снимок раз в ночь, перезапуск (JVM + снимок + журналы суток) «less than a minute» | martinfowler.com/articles/lmax.html, [прочитано] 2026-10-21 |
| Чем наш конвейер отличается | LMAX пишет в журнал **вход** до логики; мы пишем **результат** (события) после применения в памяти, поэтому состояние между применением и синхронизацией спекулятивно: ответы, представления F8 и push — только после синхронизации; при сбое — откат всех непосинхронизированных пачек и пересборка из журнала. Это решение задания 2026-10-21 (журнал событий, не команд), не прочитанный образец | `docs/research/lmax_roadmap.md`, `server/.../core/CoreWriter.java` |
| Disruptor не взят | передача идёт **пачками**: на Mac при 64 клиентах ≈ 7 тыс. передач в секунду между потоками, цикл логики на пачку 178 мкс, ожидание журнального этапа 16 мкс (JFR `herd.WriterBatch`); на 1024 клиентах узкое место — выходной этап (ответ ≈ 190 вызывающим, 2,9 мс на пачку), а не передача. Вывод: кольцевой буфер ничего не прибавил бы; `LinkedBlockingQueue`/`ArrayBlockingQueue` + `Semaphore` для обратного давления. Отдельно стоимость передачи не мерили — **[вывод]** из верхней границы цикла | замер ниже, `bench` Mac 2026-10-21 |
| Групповой коммит | пока идёт синхронизация, следующие пачки ждут и пишутся **одной записью** журнала с одной синхронизацией; Linux (btrfs, OrbStack): 3,4–3,5 пачки на синхронизацию при 64 и 256 клиентах, синхронизация занята 97–99 % времени — потолок задаёт диск | `WRITER-PIPELINE` в `WriterThroughputBenchTest` |

## Что Herd взял, чего не взял и почему
- **Взято по Р-99:** по методу на каждую из 8 экономических задач (EL §0.1) и расчёт 1 млн игроков на них (EM). Итоги в виде решений: Р-100 (вариант А), Р-101 (дополнения), Р-102 (комиссия как спред). Итоги расчётов — `topics/economy-treasury.md`.
- **Не взято:** LMSR/рамка Abernethy (меняет продукт: выплата — плечо × ход цены), DPM/паримьютуэл (нарушает «выигрыш по номиналу»), ADL (Р-90 и `game_economy_proposal.md:108,112`).
- **Своё, с пометкой:** вариант (e) «казна до λ + пул сверху»; дискретная форма Лундберга; пороги критериев EM §3.9 (50 % и др.) — «пороги — мои» (EM §3.9); правило безубыточной точности 55 % — [выбор] математика проекта (`economy_how_it_works.md` §5.2).
- **Стенд замеров:** методика открытой модели без coordinated omission (Р-99, Р-96 шаг 2); свой генератор нагрузки не пишется (LB §2.3: боты — симулятор популяции, не генератор интенсивности). Шаги 1–4 выполнены, остальные — ждут (`ROADMAP.md`).
- **Архитектура:** LMAX — направление (Р-95), не переписывать сейчас (Р-95), порядок шагов Р-96. Сделано 2026-10-18: запись итогов раунда (строки результата, истории, оракула) вынесена из-под блокировки движка — под блокировкой только событие `RoundResolved` в журнале и его применение в памяти, проекции восстанавливаются из журнала при перезапуске; удержание блокировки на раунде с 10⁴ ставок 0,82–0,95 с → 0,055–0,096 с, общее время то же; затем «решён ли раунд» решает признак в памяти движка (`ClosedRounds`, из `RoundResolved`/`RoundCancelled`, восстанавливается из журнала), а не `round_results`: курсор серии двигается сразу после коммита события (ставки на следующий раунд открываются через 59–101 мс вместо 766–1089 мс), сбой записи строк повторяется в фоне и не останавливает игру, перестройка чинит строки всех решённых раундов, сигнал оператору — `missingRoundRows` в `/api/admin/status` (`docs/research/settle_outside_lock_2026-10-18.md` §11). Гонка Java/Rust сейчас отменена: Rust строить, только если Java не уложится в бюджет на бенчмарке повтора журнала (AI §3.5, принято в LR §6).

## Расхождения и открытые вопросы
- **Написание «Ville».** EL: «Ville, 1939»; `economy_how_it_works.md` §8: «Wille 1939», а имя файла скрипта — `m4_wille_lundberg.py`. Это одно и то же неравенство; в §8 EHW исправлено на «Ville 1939» 2026-10-18.
- **Лицензия HdrHistogram** — CC0 (страница) против NOASSERTION (API); блокера нет (LB §1 строка 3).
- **Язык ядра.** LR §4 предлагал два прототипа (Java и Rust) на шаге 3; AI/LR §6: Rust — только по бюджету бенчмарка; принято второе. Оба текста сохранены.
- **Методика замеров TigerBeetle и perf-тесты Disruptor** не прочитаны; предел Gatling и wrk2 при 60 % ядер не измерен (известно: 5 000 запросов/с — 11,2 % и 5,0 % 16 ядер, bench_step4 §2).
- **Не подтверждено:** формулировки теорем Abernethy et al.; Ho & Stoll (1981); Shin (1991, 1992) в оригинале; Cont (2001) по полному тексту; проверка PFMI по оригиналу BIS; определения показателей EVE (выгрузка данных не открывалась).
- **Применимость** LMSR/DPM к плечевым выплатам Herd — [вывод], не опубликованное утверждение (EL §4, §11).
- **Данные.** Свечи — 730 суток только по BTC, ETH, SOL (Coinbase); остальные девять рынков — прокси; шансы Polymarket — одни сутки, 54 рынка (`economy_variant_a_rules_2026-10-17.md` §0.3).
