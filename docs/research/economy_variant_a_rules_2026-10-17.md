## 2. Вопрос 2. Комиссия на высоком плече

### 2.1 Что нашёл (новое по сравнению с 1M-документом)
- **[факт, `out_a3.txt`]** Сегодня `a*` (безубыточная точность) в **3-минутном** раунде: BTC 56,7 % до ×100, но 53,1 % (×240), 51,1 % (×1200); ETH 55,0 → 51,1 %; SOL 54,1 → 51,5 %. Это место уже было известно (потолок 1 %: `EconomyRules.java:32,84`).
- **[факт]** В **15-минутном** раунде `a*` низка при **любом** плече: BTC 53,1–53,3 %, ETH 52,3–52,5 %, SOL 51,96–52,7 %. Причина: комиссия `r_m·L` одна и та же, а средний ход за 15 минут в 2,22–2,23 раза больше (E|r| BTC 6,95 → 15,44 б.п.). 1M-документ считал только 3 минуты. [Новое.]
- **[факт]** `r_m` ETH, SOL, DOGE, XRP, HYPE в коде = 1,0 (`MarketEconomy.java:46-50`, `DEFAULT_FEE_BP` `:28`), а правило проекта `r_m = 0,1·σ₃` (`mcommon.py` FEE_R; `game_economy_proposal.md:88`) дало бы 1,34 / 1,73 / 1,72 / 1,53 / 1,57. Поэтому `a*` этих рынков 54,0–54,9 % против 56,6 % у BTC.

### 2.2 Опубликованное и что выбрано
- **Глостен–Милгром** (1985; спред ≥ ожидаемого выигрыша информированного; обзор `economy_literature_2026-10-17.md` §0.1 строка 5, [прочитано по обзору]). Для комиссии, пропорциональной номиналу, `a* = 1/2 + r/(2·E|r_раунда|)` — **не зависит от плеча** (выигрыш (2a−1)·L·E|r|, комиссия r·L). [вывод, вывод формулы в шапке `a3_fee_rule.py`; прогон на реальных окнах совпадает с формулой без ликвидаций.] Потолок 1 % ломает именно эту пропорциональность.
- **Hyperliquid:** комиссия от номинала, потолка нет, taker 0,045 % / maker −0,015 % (`hyperliquid.gitbook.io/hyperliquid-docs/trading/fees`, [выжимка]). **GMX:** 0,04 % / 0,06 % размера позиции при открытии и закрытии (`docs.gmx.io/docs/trading/fees/`, [выжимка]). Обе — комиссия ∝ номиналу, как правило 2а.
- **Ступени плеча по размеру позиции:** Hyperliquid (BTC 40× до 150 млн, 20× выше; `…/trading/margin-tiers`, [выжимка]); в Herd есть (A3, `EconomyRules.java:35-36`).
- **Отклонено: снизить потолок плеча до L_c = 1 %/r_m (≈ 100)** — не меняет RTP, но убирает «удвоить или обнулить»: плечо ×1000 BTC задано как замысел игры (`game_economy_proposal.md:70`). Остаётся запасным вариантом.

**Выбор:** комиссия ∝ номиналу без потолка (правило 2а), с `k` по длине раунда (2б) и подъёмом `r_m` до уровня, дающего `a*` ≥ 55 % (2в). **Порог 55 % — [выбор]:** в 1M-модели умелое меньшинство имеет точность 0,56–0,65 (§2.1 того же документа); при 55 % слабейший модельный умелый игрок только-только в плюсе; формула даёт `r_m = 0,1·E|r₃|`. Округление `r_m` вверх до 0,05 б.п. До L_c (≈ 100–109 у крипто) комиссия **та же, что сегодня** (RTP не меняется) — за исключением подъёма `r_m` у 5 рынков.

Страница спецификаций контрактов на 2026-10-17 пишет «Position limit: N/A» [выжимка] — расхождение с новостями не снято.
- **GMX:** `MAX_OPEN_INTEREST` на рынок и сторону; пул BTC/ETH на старте — 20 млн с формулировкой «меньшие лимиты относительно капитала» [выжимка: `gov.gmx.io/t/single-token-pools-gmx-v2-btc-and-eth/3348`]; параметры по рынкам задаёт Chaos Labs [сниппет].

Максимум за сутки: 3,42 (+342 %). Код: stress 0,20 для обеих длин (с множителем 2,2 для 15 минут — 0,44) (`MarketEconomy.java:42,86-90`, UNVERIFIED в самом коде). [вывод] stress 0,20 ниже 99,9 % на половине рынков (средних и тонких) и в 2,6–5 раз ниже на тонких в 15 минут; манипулятор делает не 99,9-й квантиль, а любой ход вплоть до границ цены (JELLY +400 %).

### 3.3 Правило и почему
**stress шансов = 1,00** (диапазон цены целиком) для обеих длин раунда. Лимит стороны рынка = λ·0,25 %·T / 1,00, то есть **коэффициент 0,2 к сегодняшнему лимиту 0,25 %** (эквивалент доли 0,05 % при сегодняшнем stress 0,20). Значение 1,00 — [выбор]: оно выше всех измеренных 99,9 %-квантилей, кроме тонких 15-минутных (1,14), и равно сдвигу цены через весь диапазон.

Почему масштаб по stress, а не по ликвидности в долларах (как GMX/Hyperliquid): связь «PLAY ↔ USD» неизвестна (§0.3), стоимость атаки в PLAY для манипулятора не определена. Лимит по `liquidityNum` Polymarket — следующий шаг, если появится цена PLAY; **поле в каталоге Herd не проверял** — неизвестно, читает ли сервер `liquidityNum`.

### 3.4 Эффект для 1M-толпы (`out_a4.txt`, T = 10¹², λ = 0,05)
Пиковый чистый номинал обычной толпы на сторону за раунд (все рынки) = 1,23·10⁸ PLAY. Лимит стороны рынка шансов: сегодня 6,25·10⁸, после — **1,25·10⁸**. Доля шансов в спросе толпы **неизвестна**; сценарии:
- вся толпа делится на шесть рынков шансов: отказов 0 % (спрос на рынок 2,05·10⁷); при спросе ×10 — 38,9 %;
- 50 % толпы на шансы, шесть рынков: 0 % при ×1 и ×10; 87,8 % при ×100;
- вся толпа на **один** рынок шансов: 0 % при ×1; граница 1 % достигается при спросе ×1,03; при ×10 — 89,8 %.
[вывод] Критерий C4 (< 1 %) выполняется, пока на один рынок шансов не приходится больше пикового спроса всей толпы на все рынки; при сегодняшнем stress граница была ×5,14. Параметры спроса — UNVERIFIED (1M-документ §3.9).
