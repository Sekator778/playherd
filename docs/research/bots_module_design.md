# Модуль `bots`: стратегии ботов отдельным модулем

Дата: 2026-10-16. Основание — слова Алекса 2026-10-16: «сейчас занимаемся реализацией стратегий под ботов — те правила с GitHub… вынести в отдельный модуль, чтобы всё было красиво архитектурно, по лучшим практикам программирования, по системному дизайну»; «по 2, по 3 бота под каждую стратегию»; «сейчас переписывать не надо, надо просто заложить фундамент», чтобы в будущем было легко масштабироваться. Источники правил и поведения — [`bot_behavior_sources.md`](bot_behavior_sources.md).

## 1. Что есть сейчас

- Боты — часть сервера: `server/src/main/java/crowdvsmarket/server/bots/BotService.java` (планирует ставки каждого окна, ставит через `GameService` — тот же путь проверок, что у человека) и `BotStrategy.java` (5 стратегий × 4 бота). Цену боты не видят: направление — случай или большинство прошлого раунда.
- Ставка любого рынка проходит под одной общей блокировкой записи и с записью события в Postgres внутри неё (`GameService.java:728`, `placeBet` → `persist`). Переписывать это сейчас не будем (Алекс, 2026-10-16); модуль не должен добавлять к этому пути ничего тяжёлого.
- Тики цен сервер держит в памяти (`PriceSeriesService`, «последние 15 минут» для графика); минутных свечей за час ему сейчас не нужно.

## 2. Принципы (фундамент под масштаб)

1. **Мозг бота — чистая функция.** На входе: что видно на рынке (свечи, большинство прошлого раунда), состояние бота (баланс, прошлый итог, серия), условия раунда (мин. ставка, потолок плеча для данной ставки) и генератор случайных чисел с заданным зерном. На выходе — намерения ставок. Ни сети, ни базы, ни часов, ни глобального состояния. Поэтому: детерминированные тесты и повторы; тот же код позже работает в отдельном сервисе ботов, в любом числе экземпляров (боты делятся по `botId`).
2. **Порты, а не прямые вызовы.** Модуль знает только три интерфейса: что на рынках (`MarketDataPort`), куда ставить (`BettingPort`) и что на своём счёте (`BotStatePort`), — все в терминах публичного API. Сегодня их реализует адаптер внутри сервера поверх `GameService`; завтра — клиент публичного API (HTTP/WebSocket), и боты становятся обычными внешними игроками и заодно генератором нагрузки. Модуль не зависит ни от `engine`, ни от `server`, ни от Quarkus.
3. **Сигнал и характер — раздельно.** Стратегия отвечает только «куда» (UP/DOWN и уверенность) — это правила из GitHub. Характер (persona) отвечает «сколько и с каким плечом, ставить ли вообще» — это исследования поведения частных трейдеров (`bot_behavior_sources.md`, раздел B). Любая стратегия сочетается с любым характером.
4. **Нулевые зависимости во время работы.** Только JDK 21; JUnit 5 — в тестах. Индикаторы пишем сами по формулам (RSI, EMA — десяток строк); код GPL/AGPL не копируется (лицензия проекта Apache-2.0).
5. **Дёшево на каждом шаге.** Свечи собирает сервер (read-model, §3); оценка стратегии — O(окно) по ≤ 100 свечам; никакой работы под блокировкой движка.
6. **Мягкая деградация.** Нет истории (после перезапуска, у нового рынка) — стратегия молчит, и характер решает: пропустить раунд или поставить по запасному сигналу (толпа, монетка). Бот никогда не падает и не роняет сервер.

## 3. Устройство модуля

Поправлено по ревью архитектора ([`architecture_review_2026-10-16.md`](architecture_review_2026-10-16.md) §5), 2026-10-16.

Maven-модуль `bots` (каталог `bots/`, пакет `crowdvsmarket.bots`), в корневом `pom.xml` между `engine` и `server`. Зависит от `engine` (тот — без runtime-зависимостей, `engine/pom.xml:36-37`): правила экономики (`EconomyRules`) и расчёт позиции с комиссией и ликвидацией берутся оттуда, а не переписываются.

| Пакет | Что внутри |
|---|---|
| `api` | контракты портов в терминах **публичного API** (как отдал бы `contract.ts`): `MarketSnapshot` (рынок, открыт ли приём ставок, окно раунда, минимальная ставка, потолок плеча по тирам ставки, комиссии), `BarDto` (минутная свеча), `BetRequest` / `BetResult`, `BotAccount` (баланс, итог прошлой ставки, серия) |
| `port` | `MarketDataPort` (снимки рынков, свечи рынка за N минут, большинство прошлого раунда), `BettingPort` (поставить), `BotStatePort` (состояние своего счёта) |
| `indicator` | `Sma`, `Ema`, `Rsi` (Уайлдер), `Bollinger`, `Donchian` — статические чистые функции над `double[]` |
| `signal` | `Direction`, `Signal` (направление + уверенность 0…1), интерфейс `SignalStrategy` (`id()`, `warmupBars()`, `Optional<Signal> evaluate(MarketView)`), реализации |
| `persona` | интерфейс `Persona`: какие рынки взять, ставить ли, сколько и с каким плечом; реализации |
| `brain` | `BotProfile`, `BotBrain`, `BetIntent`. Порядок: снимки всех рынков → характер выбирает рынки → сигнал по каждому → характер задаёт ставку и плечо в пределах условий рынка |
| `catalog` | состав ботов **данными** (`bots/src/main/resources/catalog.json`): `catalogId` → стратегия, параметры, характер. `catalogId` пишется в `players.bot_strategy` |
| `backtest` | `Backtester` и `BacktestMain` (CLI по файлам свечей): по каждому варианту и горизонту 3 и 15 минут — доля угаданных, доля раундов без сигнала **и итог в PLAY с комиссией и ликвидацией** через движок |

Случайность: зерно решения = `hash(botId, marketId, roundId)` — одно и то же решение воспроизводится где угодно, долгоживущего генератора нет.

Адаптеры: сегодня — внутри сервера поверх `GameService` (§7). Контрактный тест портов лежит в модуле (`test-jar`), его проходит и фейк в памяти, и любой будущий адаптер; HTTP-клиент публичного API — когда у ботов появится свой вход в API (сегодня признак бота ставит только `GameService#createBotPlayer`; решение — при подключении).

Свечи — не код модуля, а данные сервера: `priceSeries` отдаёт 15 минут и не больше 600 точек (`PriceSeriesService.java:49`), этого мало для разогрева правил на 20–55 свечей. Нужна публичная выдача минутных свечей рынка за час-два (RPC `candles`) — шаг подключения (§7). До неё бот без истории молчит (принцип 6).

## 4. Стратегии и варианты (2–3 бота на стратегию)

Правила — из `bot_behavior_sources.md` §A (идея правила, не код); параметры — предложение, проверяется прогоном по истории (§6). MACD в первом проходе не берём: это разность тех же EMA, что и в EMA cross (ревью §5); копирование трейдеров (`bot_behavior_sources.md` §C) — не в этом шаге.

| Стратегия | Правило на минутных свечах | Варианты |
|---|---|---|
| Momentum | знак изменения цены за N свечей → туда же | N = 3, 5, 15 |
| RSI reversion | RSI(n) < low → UP, > high → DOWN | (14; 30/70), (7; 25/75), (2; 10/90 — Connors RSI2) |
| Bollinger bounce | цена ниже нижней полосы → UP, выше верхней → DOWN | (20; 2,0), (20; 2,5), (10; 1,5) |
| Donchian breakout | закрытие выше максимума N свечей → UP, ниже минимума → DOWN | N = 10, 20, 55 |
| EMA cross | быстрая EMA выше медленной → UP, ниже → DOWN | (9; 21), (5; 13), (12; 26) |
| Crowd follow | большинство прошлого раунда этого рынка → туда же (нынешний Trend Follower) | 2 бота |
| Crowd contrarian | против большинства (нынешний Contrarian) | 2 бота |
| Coin | монетка (нынешний Wildcard) | 2 бота |

Итого 21 бот (сейчас 20).

## 5. Характеры (persona)

По `bot_behavior_sources.md` §B; где числа нет в источнике — это наше допущение, помечено.

| Характер | Поведение | Основа |
|---|---|---|
| Disciplined | ставит часто, плечо по «реалистичной смеси» (`BotStrategy.realisticMix`), ставка постоянная | нынешнее поведение |
| House money | после выигрыша плечо и ставка выше, после проигрыша — сброс | B5 (Thaler & Johnson 1990) |
| Loss chaser | после проигрыша плечо выше («отыграться»), после выигрыша — обычное | B5, B6 (Coval & Shumway 2005) |
| Overtrader | ставит почти в каждом раунде и на 3 рынка | B1 (Barber & Odean 2000) |
| Occasional | ставит в части раундов, на 1 рынок | B1 |
| Maximalist / Cautious | максимум разрешённого плеча / плечо 2…5 (нынешние) | нынешнее поведение |

Выбор рынка: чаще — рынки с резким движением за последние минуты (B3, «All That Glitters», 2008). Круглые суммы ставок — допущение (источника нет, `bot_behavior_sources.md` B7, UNVERIFIED).

Все ограничения игры соблюдаются как у человека: мин. ставка, одна ставка на раунд рынка, плечо ≤ потолка для этой ставки (`EconomyRules`), ставка ≤ баланса.

## 6. Проверка до подключения

1. **Прогон по истории** (`BacktestMain`) на минутных свечах из публичных API Coinbase и Hyperliquid (скрипт выгрузки — в модуле, файлы — в `.local/bots-candles/`, в git не попадают): для каждого варианта и горизонтов 3 и 15 минут — доля угаданных, доля раундов без сигнала, итог в PLAY с комиссией и ликвидацией.
2. **Разбор математика (Р-91).** Боты играют против казны (Р-92): вариант, который угадывает заметно чаще 50 % с учётом комиссии, переводит PLAY из казны ботам. Математик смотрит прогон и характеры (частота ставок, плечо после проигрыша) — сколько пакетов казна выдаёт ботам в сутки на разорения и сколько они выигрывают. Подключение — только после этого.

## 7. Подключение к серверу (следующий шаг, не в этом)

Адаптер в `server/.../bots`: `MarketDataPort` поверх нового публичного RPC `candles` (минутные свечи рынка за час-два — read-model сервера, собирается из тиков) и снимков рынков, `BettingPort` и `BotStatePort` поверх `GameService`; `BotService` вызывает `BotBrain` вместо `BotStrategy`. Переход 20 нынешних ботов на 21 новый, имена, `players.bot_strategy` = `catalogId` — отдельным планом. Выкатка — по слову Алекса.
