# Action Layer — записка к решению (2026-10-06)

Это единственный технический пункт 4-недельного обещания, который не начат: приложение `create_market / resolve / redeem` проходит локальный симулятор `chia-sdk-test` (`docs/selection/final_top3.md` §2; `the project plan` §1, §4). Срок по плану — 2026-10-15, иначе фаза 2. Записка написана для разговора с Алексом (Р-75).

Метод: исследование и одноразовый спайк вне репозитория. Агенту понадобилось около 2–3 часов. Исходники спайка сохранены в ветке `wip/action-layer-spike`, каталог `chain/market-spike/`; в сборку они не входят. Источники перечислены в конце.

## 1. Что это

**CHIP-50 (Action Layer and Slots)** — внутренний слой синглтона, статус Final.
- У синглтона есть постоянное состояние и набор действий.
- Пазлы действий лежат в merkle-дереве, а его корень вшит в каррирование.
- Reserve-финализатор ведёт резерв CAT.
- CHIP прямо говорит: новое приложение требует полного аудита.

Готового рынка предсказаний на Chia нет: `gh search repos "prediction market chia"` на 2026-10-06 дал 0 репозиториев.

Как это ложится на Herd, по спайку:

| Часть | Как устроена |
|---|---|
| Рынок | один синглтон; состояние `(reserve, status, outcome)` |
| Параметры | порог цены, `close_ts`, окно `grace` — вкаррированы в действия |
| Резерв | монета PLAY CAT, тратить её может только рынок |
| YES/NO | два CAT с TAIL `EverythingWithSingleton` |

Действия:
- **`create_market`** — запуск синглтона драйвером на Rust, своего Rue-кода не требует.
- **`mint`** — внести X PLAY и получить X YES и X NO.
- **`resolve`** — по записи оракула: YES, если цена не ниже порога.
- **`redeem`** — сжечь X выигрышных токенов и получить X PLAY.

## 2. Что показал спайк

- Действия на Rue компилируются: `resolve` 282 байта CLVM, `mint` 563, `redeem` 522.
- Полный честный цикл прошёл в `chia-sdk-test::Simulator`:
  1. выпуск PLAY;
  2. запуск оракула;
  3. запуск рынка;
  4. `mint` 600;
  5. `resolve` → YES;
  6. `redeem` 600.
- Отрицательные тесты (всего 12 тестов, `cargo test` за 0,9 с):
  - `mint` без взноса;
  - `redeem` до `resolve` и проигравшей стороной;
  - подмена адреса выплаты;
  - повторный `mint` после `resolve`;
  - неверный announcement;
  - `resolve` до `close_ts`.
- Стоимость бандлов: `mint` 192 383 514, `resolve` 98 863 362, `redeem` 127 842 377. Лимит блока — 11 000 000 000; бандл оракула — около 30 000 000.

Подводные камни:
- Авторизацию пришлось привязать к адресу через puzzle announcement: иначе наблюдатель мог перехватить выплату.
- Каждый спенд рынка тратит и резервную монету, поэтому два игрока в одном блоке конфликтуют.
- Rue 0.8.5 падает с паникой вместо диагностики.
- Хеш `mint` на Rue 0.8.5 и 0.10.0 разный: версию компилятора надо пинить, а скомпилированные хеши — коммитить.

## 3. Чего не хватает и чем рискуем

1. **Связка с оракулом.** Сегодняшний announcement оракула — сырая CLVM-сериализация, которую пазл не воспроизводит.
   - Вариант (i): добавочный announcement `tree_hash(запись)` в публикатор. Это правка работающего публикатора, 1746 строк.
   - Вариант (ii): `resolve` по подписи ключа оракула — та же модель доверия.
2. **Нет `void`.** Если оракул не дал запись в окне, резерв заперт навсегда.
3. **Безопасность.** Это новый пазл с резервом, независимой проверки нет. Прецедент: TibetSwap закрылся 2026-09-10 после эксплойта (`the project plan` §2).
4. **Лицензии образцов.** `Yakuhito/slot-machine` — Prosperity Public License 3.0.0 (некоммерческая), `xch-dev/auctions` — без лицензии. Код из них не копировался. Пазлы из крейтов SDK — Apache-2.0.
5. **Связи с игрой нет.** Раунды и плечо живут в базе сервера (Р-6), рынок на цепи — отдельный объект на том же PLAY.

## 5. Рекомендация

Вариант **(c)**: работа сделана примерно на 70%, остаётся упаковка на день. Пункт обещания закрывается в его формулировке, и работающий оракул не трогается.

Если до 2026-10-15 останется время, добавлять по порядку:
1. `void`;
2. независимую проверку;
3. связку с оракулом — вариант (d) по подписи проще.

Подключение к продукту (интерфейс, команды `c2 market-*`, формат announcement) — решения продукта по Р-75.
